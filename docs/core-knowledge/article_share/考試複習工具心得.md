我最近在思考一件事：想把 Agent Coding 真的跑起來，關鍵應該是在 
1. 規格能不能持續產生
2. 程式能不能被嚴格檢驗
＿＿＿

因為只要 spec 不穩、檢驗不夠嚴，
整個流程就會變成反覆試錯的迴圈，越跑越亂。

往上追會發現，spec 的品質其實源自需求判斷，
需求如果一開始就模糊，
後面再多工具也只是把模糊放大。
＿＿＿

所以我先挑一個專案來做實驗：
先做一個「產出好需求」的 PM Agent。
需求往 spec 轉換這段，
市面上工具很多，反而相對不缺；
＿＿＿
我現在比較想補的是更上游：
把需求定義做扎實、做可交棒，
讓 AI 接到的每張卡都像工程任務一樣清楚。
＿＿＿
我把這個目標叫做 可執行的需求定義：
交給 AI 之前，
先把問題描述寫清楚、範圍切乾淨、
驗收標準講到可以測。
像「提升性能」這種句子太鬆了，
換成「把報表生成時間從 5 秒降到 2 秒，
且在 10,000 筆資料測試下達成」就會很有力量。
＿＿＿
輸入一清楚，AI 的輸出就更可預期，
來回修正也會少很多，
整個系統的干擾源會被壓下來。
＿＿＿
做法上我用 repo 當作 PM 的工作台：
Signals → Opportunities → Requirements 這條管線固定下來，
檔案和連結用 Single Source of Truth 管住，
再把重複性工作做成 Agent Skills + 腳本，
像是引用完整性檢查、
需求 ready 檢查、tag 關聯分析、
shaping 文件與 acceptance 條件生成。
＿＿＿＿
PM 就把時間留給真正需要人負責的判斷：
這個需求值不值得做、
是不是切對 slice、是不是符合產品目標。
＿＿＿
等這條「需求可執行」的管線穩了，
我才會開始更深入研究 嚴格品質門檻（Quality Gates）。

那一段比較像是在 AI 輸出和正式環境之間加一個控制閥：
測試要全綠、lint 要過、資安掃描要乾淨、
敏感資訊不能外流；
CI 沒過就擋在 PR 上。
這樣下游才能放心接，整條鏈路才會變得可持續。
＿＿＿
目前我對這件事的感覺很踏實：
工具可以慢慢換，
流程和標準先站穩。
把需求寫到能被驗收，
把輸出放進能被檢驗的管道，
Agent Coding 才會開始像一套可靠的系統。

我最近做了一件很類似的事，
只是領域不一樣：我在準備 Databricks 認證考試。
＿＿＿

一開始很單純，就是刷題、整理錯題，
但刷到第 50 題左右我發現，
這東西沒有系統就會變成記憶負擔：
題目散在各處、知識點重複出現、
錯誤選項的陷阱沒被好好拆解。
＿＿＿

後來我決定用跟 PM Agent 類似的思路：
不是只記「答案」，而是建立 可複用的知識結構。
＿＿＿

具體來說我做了幾件事：

第一是把題目從流水號改成主題分類，
像是 Delta Lake、Streaming、Unity Catalog 這些，
每個主題下再按難度分 L1/L2/L3。
這樣複習的時候就能集中火力，
而不是隨機跳來跳去。
＿＿＿

第二是把每題的解析拆成固定結構：
考點識別、正解說明、錯誤排除、記憶法、官方文件。
尤其是「錯誤排除」這塊，
我會逐一分析每個選項為什麼錯、陷阱怎麼設計的，
因為考試最容易失分的就是「看起來對但其實錯」的選項。
＿＿＿

第三是開始寫 速記文件。

我發現很多知識點會重複考，
像是 Auto Loader 的 schema evolution 模式、
Streaming trigger 的語法、
Unity Catalog 的權限語法，
這些東西如果每次都要回去翻題目，效率太低。
＿＿＿

所以我就把它們抽出來，
寫成 一頁式速記：
一句話結論 + 對照表 + 常見陷阱 + 10 秒記憶法。
＿＿＿

這週我一口氣建了 12 個速記文件：
- Auto Loader schema evolution/location
- Structured Streaming trigger 語法
- Streaming 資料品質隔離架構
- PySpark Window Functions
- Spark UI SQL Metrics
- Databricks CLI 高頻指令
- Unity Catalog 權限與遮罩語法
- Delta Sharing 認證機制
- Delta Time Travel 語法

每個都是 30 秒能掃完的濃縮版，
考前翻一遍就能快速喚醒記憶。
＿＿＿

第四是把「不熟的題目」變成追蹤清單。

我不只記編號，還會寫下具體的知識點，
像是「Q-028 欄位遮罩語法」、
「Q-039 Auto Loader 的 addNewColumns 模式」。
＿＿＿

這樣過幾天回來複習時，
我不用重新想「這題在考什麼」，
直接看備註就知道要複習哪個概念。
＿＿＿

最後一件事是寫了一份 創意學習方法 的文件。

裡面整理了一些記憶技巧：
像是反向題目法（用答案反推題幹）、
錯題可視化（把直覺理由和真實原因做對照）、
間隔複習地圖（在不熟題目上標 D1/D3/D7）。
＿＿＿

這些方法不是我發明的，
大多來自認知科學的研究，
但重點是把它們 落地成可操作的流程，
而不只是知道有這個概念。
＿＿＿

現在整個 repo 有接近 200 道題，
每題都有完整解析，
還有 12 份速記、3 份核心知識筆記、
外加一套學習方法論。
＿＿＿

我覺得這件事跟做 PM Agent 很像：
都是在建立 可複用的知識資產。
＿＿＿

題目會做完、考試會考完，
但這套拆解問題、建立結構、沉澱知識的流程，
可以套用到任何需要快速學習的場景。
＿＿＿

最關鍵的是：
結構一旦穩了，後續的維護成本就會很低。
新增一題只需要 3 分鐘、
更新一份速記只需要 5 分鐘，
因為格式、標籤、檢查清單都已經固定下來了。
＿＿＿

這種感覺很踏實。

不是靠記憶力硬撐，
而是靠系統幫你記住、
靠結構幫你快速提取。
＿＿＿

考試這件事最終會結束，
但這套方法論會留下來。
