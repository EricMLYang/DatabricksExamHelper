我最近在準備 Databricks 認證考試。
＿＿＿

一開始很單純，就是刷題、整理錯題，
但刷到第 50 題左右我發現，
這東西沒有系統就會變成記憶負擔：
題目散在各處、知識點重複出現、
錯誤選項的陷阱沒被好好拆解。
＿＿＿

後來我決定把它系統化：
不是只記「答案」，而是建立 可複用的知識結構。
＿＿＿

具體來說我做了幾件事：

第一是把題目從流水號改成主題分類，
像是 Delta Lake、Streaming、Unity Catalog 這些，
每個主題下再按難度分 L1/L2/L3。
這樣複習的時候就能集中火力，
而不是隨機跳來跳去。
＿＿＿

第二是把每題的解析拆成固定結構：
考點識別、正解說明、錯誤排除、記憶法、官方文件。
尤其是「錯誤排除」這塊，
我會逐一分析每個選項為什麼錯、陷阱怎麼設計的，
因為考試最容易失分的就是「看起來對但其實錯」的選項。
＿＿＿

第三是開始寫 速記文件。

我發現很多知識點會重複考，
像是 Auto Loader 的 schema evolution 模式、
Streaming trigger 的語法、
Unity Catalog 的權限語法，
這些東西如果每次都要回去翻題目，效率太低。
＿＿＿

所以我就把它們抽出來，
寫成 一頁式速記：
一句話結論 + 對照表 + 常見陷阱 + 10 秒記憶法。
＿＿＿

這週我一口氣建了 12 個速記文件：
- Auto Loader schema evolution/location
- Structured Streaming trigger 語法
- Streaming 資料品質隔離架構
- PySpark Window Functions
- Spark UI SQL Metrics
- Databricks CLI 高頻指令
- Unity Catalog 權限與遮罩語法
- Delta Sharing 認證機制
- Delta Time Travel 語法

每個都是 30 秒能掃完的濃縮版，
考前翻一遍就能快速喚醒記憶。
＿＿＿

第四是把「不熟的題目」變成追蹤清單。

我不只記編號，還會寫下具體的知識點，
像是「Q-028 欄位遮罩語法」、
「Q-039 Auto Loader 的 addNewColumns 模式」。
＿＿＿

這樣過幾天回來複習時，
我不用重新想「這題在考什麼」，
直接看備註就知道要複習哪個概念。
＿＿＿

最後一件事是寫了一份 創意學習方法 的文件。

裡面整理了一些記憶技巧：
像是反向題目法（用答案反推題幹）、
錯題可視化（把直覺理由和真實原因做對照）、
間隔複習地圖（在不熟題目上標 D1/D3/D7）。
＿＿＿

這些方法不是我發明的，
大多來自認知科學的研究，
但重點是把它們 落地成可操作的流程，
而不只是知道有這個概念。
＿＿＿

現在整個 repo 有接近 200 道題，
每題都有完整解析，
還有 12 份速記、3 份核心知識筆記、
外加一套學習方法論。
＿＿＿

這套方法的核心，其實就是在建立 可複用的知識資產。
＿＿＿

題目會做完、考試會考完，
但這套拆解問題、建立結構、沉澱知識的流程，
可以套用到任何需要快速學習的場景。
＿＿＿

最關鍵的是：
結構一旦穩了，後續的維護成本就會很低。
新增一題只需要 3 分鐘、
更新一份速記只需要 5 分鐘，
因為格式、標籤、檢查清單都已經固定下來了。
＿＿＿

這種感覺很踏實。

不是靠記憶力硬撐，
而是靠系統幫你記住、
靠結構幫你快速提取。
＿＿＿

考試這件事最終會結束，
但這套方法論會留下來。
