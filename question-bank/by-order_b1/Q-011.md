## 題目內容
### 題幹
A data engineer has a PySpark DataFrame with the following columns: `employee_name`, `department`, and `salary`. They want to assign a tier to each employee within their department based on salary, where employees earning the same salary share the same tier.

To achieve this, they define a window by department and order by salary in descending order:

```python
window_spec = Window.partitionBy("department").orderBy(df["salary"].desc())
```

Which of the following functions correctly use this window to calculate the tier column?

### 選項
- **A.** `df.withColumn("tier", percent_rank().over(window_spec))`
- **B.** `df.withColumn("tier", row_number().over(window_spec))`
- **C.** `df.withColumn("tier", rank().over(window_spec))`
- **D.** `df.withColumn("tier", dense_rank().over(window_spec))`

# 題目解析

---

## 📍 考點識別
**核心技術:** PySpark Window Functions (Ranking Functions)
**關鍵概念:** dense_rank() vs rank() vs row_number() vs percent_rank()
**題目關鍵字：**
- **Window Function**: 在特定分區內進行計算的函數
- **partitionBy**: 按部門分組
- **Ranking Functions**: 排名函數家族的差異
- **Consecutive Tiers**: 連續的等級編號（相同薪資同等級）

---

## ✅ 正解說明
### 為什麼 D 是正確答案？

**技術原理：**

題目要求：
1. **相同薪資 = 相同等級**（同一 tier）
2. **連續編號**（1, 1, 2 而非 1, 1, 3）

`dense_rank()` 正好符合這兩個需求：

```python
from pyspark.sql.window import Window
from pyspark.sql.functions import dense_rank

window_spec = Window.partitionBy("department").orderBy(df["salary"].desc())
df_with_tier = df.withColumn("tier", dense_rank().over(window_spec))
```

**範例輸出：**

| employee_name | department | salary | tier |
|---------------|------------|--------|------|
| Alice         | Sales      | 8000   | 1    |
| Bob           | Sales      | 8000   | 1    |
| Charlie       | Sales      | 7000   | 2    | ← 連續編號
| David         | Sales      | 6000   | 3    |
| Eve           | Engineering| 9000   | 1    |
| Frank         | Engineering| 8500   | 2    |

**為什麼是 dense_rank()？**
- ✅ **處理相同值**：相同薪資給予相同排名
- ✅ **連續編號**：不會跳號（1, 1, 2, 3...）
- ✅ **分區獨立**：每個部門獨立計算排名

## ❌ 錯誤選項排除

### A. `percent_rank().over(window_spec)`
**為什麼錯誤？**
- **回傳值類型錯誤**：`percent_rank()` 回傳 0 到 1 之間的**小數**，而非整數等級
- **計算公式**：`(rank - 1) / (total_rows - 1)`
- **範例輸出**：0.0, 0.0, 0.5, 1.0（不符合整數 tier 需求）

```python
# 錯誤輸出範例
| employee | salary | percent_rank |
|----------|--------|--------------|
| Alice    | 8000   | 0.0          |
| Bob      | 8000   | 0.0          |
| Charlie  | 7000   | 0.666        |
| David    | 6000   | 1.0          |
```

### B. `row_number().over(window_spec)`
**為什麼錯誤？**
- **無法處理相同值**：即使薪資相同，每一行也會得到**唯一的編號**
- **不符合需求**：相同薪資應該有相同 tier

```python
# 錯誤輸出範例
| employee | salary | row_number |
|----------|--------|------------|
| Alice    | 8000   | 1          |
| Bob      | 8000   | 2          | ← 應該是 1
| Charlie  | 7000   | 3          |
```

### C. `rank().over(window_spec)`
**為什麼錯誤？**
- **會跳號**：遇到相同值後，下一個排名會**跳過中間的數字**
- **不連續**：產生 1, 1, 3, 4（而非 1, 1, 2, 3）

```python
# 錯誤輸出範例
| employee | salary | rank |
|----------|--------|------|
| Alice    | 8000   | 1    |
| Bob      | 8000   | 1    |
| Charlie  | 7000   | 3    | ← 跳過 2
| David    | 6000   | 4    |
```

**陷阱設計：**
`rank()` 與 `dense_rank()` 最容易混淆，差別僅在於是否跳號。

## 🧠 記憶法

### 口訣
**「Dense 不跳號，Rank 會跳號，Row 全唯一，Percent 變小數」**

### 比較表：四大排名函數

| 函數 | 相同值處理 | 編號特性 | 回傳類型 | 使用場景 |
|------|-----------|---------|---------|---------|
| **dense_rank()** | ✅ 相同排名 | 連續不跳號 (1,1,2,3) | 整數 | 🎯 **連續等級分層** |
| **rank()** | ✅ 相同排名 | 會跳號 (1,1,3,4) | 整數 | 競賽排名（並列第一，沒有第二名） |
| **row_number()** | ❌ 唯一編號 | 連續 (1,2,3,4) | 整數 | 需要唯一識別碼 |
| **percent_rank()** | ✅ 相同排名 | 0-1 之間 | 小數 | 百分位排名 |

### 視覺化對比

```
薪資: 100, 100, 90, 80

dense_rank():   1,  1,  2,  3  ← 不跳號 ✅
rank():         1,  1,  3,  4  ← 跳號
row_number():   1,  2,  3,  4  ← 全唯一
percent_rank(): 0, 0, 0.66, 1  ← 小數
```

### 記憶點
- **Dense** = **密集**的，所以數字密集不跳號
- **Rank** = 傳統排名，並列後會空位
- **Row Number** = 行號，當然每行唯一
- **Percent Rank** = 百分比，當然是小數
