## ✅ 正解說明
### 為什麼 C 是正確答案？

**Integration Testing 測試模組間的整合與互動**：
- 確保不同模組組合後能正常運作
- 驗證資料流在模組間的傳遞
- 發現介面和整合問題

#### 測試類型比較
```
測試金字塔：

        ┌───────────┐
        │  E2E Test │  ← 最少
        ├───────────┤
        │Integration│  ← 本題
        ├───────────┤
        │ Unit Test │  ← 最多
        └───────────┘
```

#### Integration Testing 範例
```python
# 整合測試範例：測試 ETL Pipeline 各階段的整合

def test_bronze_to_silver_integration():
    # 準備測試資料
    test_data = create_bronze_test_data()

    # 執行 Bronze → Silver 轉換
    result = run_bronze_to_silver(test_data)

    # 驗證結果
    assert result.count() > 0
    assert "cleaned_column" in result.columns
    assert result.filter("cleaned_column IS NULL").count() == 0

def test_silver_to_gold_integration():
    # 測試 Silver → Gold 的整合
    silver_data = create_silver_test_data()
    result = run_silver_to_gold(silver_data)

    # 驗證聚合邏輯
    assert result.count() == expected_count
```

## ❌ 錯誤選項排除

### A. 驗證功能符合業務需求
**為什麼錯誤？**
- **這描述的是 Functional Testing（功能測試）**
- 驗證功能是否符合規格
- 不專注於模組間的整合

### B. 模擬使用者體驗
**為什麼錯誤？**
- **這描述的是 End-to-End Testing（端對端測試）**
- 或 User Acceptance Testing（使用者驗收測試）
- 從使用者角度測試整個系統

### D. 測試單一程式碼單元
**為什麼錯誤？**
- **這描述的是 Unit Testing（單元測試）**
- 測試最小的程式碼單元（函數、方法）
- 不涉及模組間的互動

## 🧠 記憶法
### 口訣
**「單元測函數，整合測連接，E2E 測全程」**

### 測試類型比較表
| 測試類型 | 測試對象 | 範例 |
|----------|----------|------|
| Unit Test | 單一函數 | 測試 parse_date() |
| Integration Test | 模組間整合 | 測試 Bronze → Silver |
| E2E Test | 整個系統 | 測試完整 ETL 流程 |
| Functional Test | 業務功能 | 測試報表產生 |

### Data Engineering 測試策略
```
資料工程測試策略：
├── Unit Test → 轉換邏輯、UDF
├── Integration Test → 各層之間的資料流
├── Data Quality Test → 資料品質規則
└── E2E Test → 完整 Pipeline
```
