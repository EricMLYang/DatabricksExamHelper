## ✅ 正解說明
### 為什麼 C 是正確答案？

**Insert-only merge 只需要 `WHEN NOT MATCHED` 子句**：
- 只處理不匹配的記錄（新記錄）
- 匹配的記錄（已存在）自動被忽略
- 不需要額外的 WHEN MATCHED 子句

#### Insert-only Merge 語法
```sql
MERGE INTO target_table
USING source_table
ON merge_condition
WHEN NOT MATCHED
    INSERT *
```

#### 行為說明
```
Insert-only Merge 行為：
source_id | target_id | 結果
----------|-----------|------
1         | 1         | 忽略（已存在）
2         | 2         | 忽略（已存在）
3         | (無)      | 插入（新記錄）
4         | (無)      | 插入（新記錄）
```

### 選項 A - 錯誤
**問題:** `IGNORE *` 不是有效的 MERGE 語法

**問題:** `WHEN MATCHED INSERT *` 語法錯誤
- MATCHED 條件下不能執行 INSERT
- INSERT 只能用於 `WHEN NOT MATCHED`
- 應該使用 UPDATE 或 DELETE

### 2. **補充 MERGE 完整語法說明**

```markdown
## 📚 補充知識

### MERGE INTO 完整語法結構
```sql
MERGE INTO target_table
USING source_table
ON merge_condition
WHEN MATCHED [AND condition]
    THEN UPDATE SET ... | DELETE
WHEN NOT MATCHED [AND condition]
    THEN INSERT ...
WHEN NOT MATCHED BY SOURCE [AND condition]
    THEN UPDATE SET ... | DELETE
```

### 三種常見 Merge 模式

#### 1️⃣ Insert-only Merge (本題)
```sql
MERGE INTO orders
USING new_orders
ON orders.order_id = new_orders.order_id
WHEN NOT MATCHED
    THEN INSERT *
```
**用途:** 只插入新記錄,已存在記錄保持不變

#### 2️⃣ Upsert (Update + Insert)
```sql
MERGE INTO orders
USING new_orders
ON orders.order_id = new_orders.order_id
WHEN MATCHED
    THEN UPDATE SET *
WHEN NOT MATCHED
    THEN INSERT *
```
**用途:** 更新已存在記錄,插入新記錄

#### 3️⃣ SCD Type 2 Pattern
```sql
MERGE INTO orders
USING new_orders
ON orders.order_id = new_orders.order_id
WHEN MATCHED AND orders.status <> new_orders.status
    THEN UPDATE SET end_date = current_timestamp(), is_current = false
WHEN NOT MATCHED
    THEN INSERT *
```
**用途:** 保留歷史變更記錄
```

### 3. **實務陷阱提醒**

```markdown
## ⚠️ 常見陷阱

### Trap 1: 混淆 INSERT 的使用時機
- ✅ `WHEN NOT MATCHED THEN INSERT` - 正確
- ❌ `WHEN MATCHED THEN INSERT` - 錯誤 (已存在無法再 INSERT)

### Trap 2: 誤用 IGNORE 關鍵字
- Delta Lake MERGE 語法**沒有** `IGNORE` 關鍵字
- 若不想處理某種情況,直接省略該 WHEN 子句即可

### Trap 3: 混淆省略行為
- 省略 `WHEN MATCHED` → 匹配記錄**保持不變** (Insert-only)
- 省略 `WHEN NOT MATCHED` → 新記錄**不會插入** (Update-only/Delete-only)
```

### 4. **性能考量補充**

```markdown
## 🚀 性能最佳實踐

### Insert-only Merge 優化建議

1. **使用 Z-Ordering**
```sql
OPTIMIZE orders ZORDER BY (order_id)
```
加速 merge condition 的查找

2. **考慮分區策略**
```sql
-- 如果資料有時間特性
MERGE INTO orders
USING new_orders
ON orders.order_id = new_orders.order_id 
   AND orders.order_date = new_orders.order_date
WHEN NOT MATCHED
    THEN INSERT *
```

3. **大量插入時考慮替代方案**
如果 99% 都是新記錄,可能直接用:
```sql
INSERT INTO orders
SELECT * FROM new_orders
WHERE order_id NOT IN (SELECT order_id FROM orders)
```
或使用 LEFT ANTI JOIN 會更快
```
