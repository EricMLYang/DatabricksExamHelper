## ✅ 正解說明
### 為什麼 D 是正確答案？

**DBU Cost 不是 Spark UI 的指標**：
- DBU (Databricks Unit) 是 Databricks 的計費單位
- Spark UI 是開源 Apache Spark 的元件
- Spark UI 顯示的是執行效能指標，不是計費資訊

#### Spark UI Stage Metrics 實際內容
```
Spark UI Stage Details 包含：
├── Summary Metrics for Completed Tasks
│   ├── Duration
│   ├── GC Time
│   ├── Spill (Memory)
│   ├── Spill (Disk)
│   ├── Input Size
│   ├── Output Size
│   ├── Shuffle Read
│   └── Shuffle Write
│
├── Aggregated Metrics by Executor
│   ├── Executor ID
│   ├── Address
│   ├── Task Time
│   └── Total Tasks
│
└── Tasks Table
    ├── Task ID
    ├── Status
    ├── Duration
    └── Errors
```

#### DBU 是什麼？
```
DBU (Databricks Unit)：
├── 定義 → Databricks 處理能力的計費單位
├── 計算 → 依據 VM 類型和執行時間
├── 位置 → Databricks 帳單系統，不在 Spark UI
└── 用途 → 成本計算和預算規劃
```

#### Spark UI vs Databricks 監控
| 監控工具 | 顯示內容 | DBU 資訊 |
|----------|----------|----------|
| Spark UI | 執行效能指標 | ❌ 無 |
| Databricks Console | 成本和效能 | ✅ 有 |
| System Tables | 歷史資料 | ✅ 有 |

## ❌ 錯誤選項排除

### A. Spill (Disk and Memory)
**為什麼錯誤？（這是 Spark UI 的指標）**
- **Shuffle Spill 是重要的效能指標**
- Memory Spill：資料超出記憶體時序列化到記憶體的大小
- Disk Spill：資料溢出到磁碟的大小

```
Spill 指標意義：
├── Spill (Memory) → 反序列化後的資料大小
├── Spill (Disk) → 序列化後寫入磁碟的大小
└── 高 Spill → 記憶體不足，效能下降
```

### B. Duration
**為什麼錯誤？（這是 Spark UI 的指標）**
- **Duration 是最基本的執行時間指標**
- 顯示每個 Task 的執行時間
- 是效能分析的核心指標

### C. GC time
**為什麼錯誤？（這是 Spark UI 的指標）**
- **GC Time 是 JVM 垃圾回收時間**
- 高 GC Time 表示記憶體壓力大
- 是調校記憶體的重要參考

```
GC Time 意義：
├── 高 GC Time → 記憶體不足
├── 頻繁 GC → 需要增加 executor 記憶體
└── 正常範圍 → 佔執行時間 < 10%
```

## 🧠 記憶法
### 口訣
**「Spark UI 看效能，DBU 成本找帳單」**

### Spark UI Stage Metrics 完整列表
| 指標 | 說明 | 調校意義 |
|------|------|----------|
| Duration | 執行時間 | 整體效能 |
| GC Time | 垃圾回收時間 | 記憶體壓力 |
| Spill (Memory) | 記憶體溢出 | 記憶體不足 |
| Spill (Disk) | 磁碟溢出 | 嚴重記憶體不足 |
| Input Size | 輸入資料量 | 資料規模 |
| Shuffle Read | Shuffle 讀取量 | 網路傳輸 |
| Shuffle Write | Shuffle 寫入量 | 資料分布 |

### Spark UI 層級結構
```
Spark UI 導覽：
├── Jobs → 顯示所有 Jobs
│   └── Job Details → 顯示 Stages
│       └── Stage Details → 顯示 Tasks 和 Metrics
├── Stages → 直接查看所有 Stages
├── Storage → 快取資訊
├── Environment → 設定資訊
└── Executors → 執行器資訊
```

### 效能問題診斷指南
```
Spark UI 指標診斷：
├── Duration 過長 → 檢查資料傾斜
├── GC Time 過高 → 增加 executor 記憶體
├── Spill 過大 → 增加分區數或記憶體
└── Shuffle 過大 → 優化 Join 策略
```
