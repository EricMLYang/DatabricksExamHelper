## ✅ 正解說明
### 為什麼 D 是錯誤的（正確答案）？

**Cluster Policies 不支援排程叢集啟停時間**：
- 排程功能需要使用 Jobs 或自動化腳本
- Cluster Policies 專注於「配置規範」
- 不是時間控制工具

#### Cluster Policies 功能
```
Cluster Policies 可以做的事：
├── 控制成本 → 限制 VM 類型、數量
├── 統一配置 → Spark 設定、環境變數
├── 強制套件 → 預設安裝的 Libraries
├── 權限控制 → 誰可以建立什麼類型的叢集
└── 不能做 → 排程啟停時間 ❌
```

#### 排程替代方案
```python
# 排程叢集啟停需要使用其他方式：

# 方式 1: Databricks Jobs
# 在 Job 中設定 cluster 配置，Job 執行時自動啟動

# 方式 2: REST API + 排程工具
# 使用 cron、Azure Functions、AWS Lambda 等
# 呼叫 Databricks REST API 啟停叢集

# 方式 3: Databricks CLI + cron
# databricks clusters start --cluster-id xxx
# databricks clusters delete --cluster-id xxx
```

## ❌ 其他選項為何正確

### A. 控制成本
**這是 Cluster Policies 的功能**：
- 限制 VM 類型
- 限制節點數量
- 限制自動擴展範圍

### B. 確保一致的配置
**這是 Cluster Policies 的核心功能**：
- 統一 Spark 配置
- 統一環境變數
- 統一系統設定

### C. 強制套件安裝
**這是 Cluster Policies 的功能**：
- 定義預設 Libraries
- 強制安裝特定版本
