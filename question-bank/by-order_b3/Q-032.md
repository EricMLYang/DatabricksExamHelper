## 題目內容
### 題幹
<!-- ⚠️ 保持英文原文，不要翻譯 -->
The data engineering team has a large Delta table named 'users'. A recent query on the table returned some entries with negative values in the 'age' column.

To avoid this issue and enforce data quality, a junior data engineer decided to add a CHECK constraint to the table with the following command:

```sql
ALTER TABLE users ADD CONSTRAINT valid_age CHECK (age > 0);
```

However, the command fails when executed.

Which statement explains the cause of this failure?

### 選項
<!-- ⚠️ 保持英文原文，不要翻譯 -->
- **A.** The users table already contains rows that violate the new constraint; all existing rows must satisfy the constraint before adding it to the table.
- **B.** The users table already exists; CHECK constraints can only be added during table creation using CREATE TABLE command.
- **C.** The users table already contains rows; CHECK constraints can only be added on empty tables.
- **D.** The syntax for adding the CHECK constraint is incorrect. Instead, the command should be: `ALTER TABLE users ADD CONSTRAINT ON COLUMN age (CHECK > 0)`

# 題目解析

---

## 📍 考點識別
**核心技術:** Delta Lake CHECK Constraint
**關鍵概念:** 約束新增時的驗證行為
**題目關鍵字：**
- **CHECK constraint**: 檢查約束
- **command fails**: 指令失敗
- **negative values**: 負值（違反約束的資料）

---

## ✅ 正解說明
### 為什麼 A 是正確答案？

**ADD CONSTRAINT 會驗證所有現有資料**：
- 新增約束前會檢查所有現有記錄
- 如果有任何記錄違反約束，指令會失敗
- 必須先清理違規資料才能新增約束

#### CHECK Constraint 新增流程
```
ADD CONSTRAINT 執行流程：
    執行 ADD CONSTRAINT
           │
           ▼
    掃描所有現有資料
           │
    ┌──────┴──────┐
    │ 有違規資料？ │
    └──────┬──────┘
      是   │   否
      │    │
      ▼    ▼
    失敗  成功新增約束
```

#### 錯誤訊息範例
```
Error: CHECK constraint valid_age violated by existing data.
Some rows in table users violate the constraint.

-- 違規記錄可能類似：
-- user_id | age
-- 123     | -5   ← 違反 age > 0
-- 456     | -10  ← 違反 age > 0
```

#### 解決方法
```sql
-- 方法 1: 刪除違規資料
DELETE FROM users WHERE age <= 0;

-- 方法 2: 更新違規資料
UPDATE users SET age = NULL WHERE age <= 0;

-- 方法 3: 先查看違規資料再決定
SELECT * FROM users WHERE age <= 0;

-- 清理後再新增約束
ALTER TABLE users ADD CONSTRAINT valid_age CHECK (age > 0);
```

---

## ❌ 錯誤選項排除

### B. CHECK constraints 只能在 CREATE TABLE 時新增
**為什麼錯誤？**
- **可以用 ALTER TABLE 新增約束**
- Delta Lake 支援對現有表格新增約束
- 語法完全正確

```sql
-- 兩種方式都可以新增 CHECK constraint：

-- 方式 1: CREATE TABLE 時
CREATE TABLE users (
    user_id INT,
    age INT,
    CONSTRAINT valid_age CHECK (age > 0)
);

-- 方式 2: ALTER TABLE（後續新增）
ALTER TABLE users ADD CONSTRAINT valid_age CHECK (age > 0);
```

### C. CHECK constraints 只能在空表上新增
**為什麼錯誤？**
- **可以在有資料的表格上新增**
- 只要現有資料都符合約束條件
- 問題不是「有資料」，而是「有違規資料」

```
關鍵區別：
├── 有資料但都符合約束 → 可以新增 ✅
├── 有資料且有違規 → 失敗 ❌
└── 不是「空表」的問題
```

### D. 語法錯誤
**為什麼錯誤？**
- **原始語法完全正確**
- `ALTER TABLE ... ADD CONSTRAINT ... CHECK (...)` 是標準語法
- 選項 D 的語法才是錯誤的

```sql
-- 正確語法
ALTER TABLE users ADD CONSTRAINT valid_age CHECK (age > 0);

-- 錯誤語法（選項 D）
ALTER TABLE users ADD CONSTRAINT ON COLUMN age (CHECK > 0);  -- 錯誤！
```

## 🧠 記憶法
### 口訣
**「新增約束先檢查，違規資料要先清」**

### CHECK Constraint 行為比較
| 操作 | 驗證現有資料 | 驗證新增資料 |
|------|-------------|-------------|
| ADD CONSTRAINT | ✅ 是 | ✅ 是 |
| INSERT/UPDATE | N/A | ✅ 是 |

### 常見 CHECK Constraint 範例
```sql
-- 數值範圍
ALTER TABLE products
ADD CONSTRAINT valid_price CHECK (price >= 0);

-- 字串長度
ALTER TABLE users
ADD CONSTRAINT valid_email CHECK (length(email) > 0);

-- 列舉值
ALTER TABLE orders
ADD CONSTRAINT valid_status CHECK (status IN ('pending', 'completed', 'cancelled'));
```

### 新增約束前的檢查流程
```
最佳實踐：
1. 先查詢違規資料數量
   SELECT COUNT(*) FROM table WHERE NOT (constraint_condition);

2. 檢視違規資料內容
   SELECT * FROM table WHERE NOT (constraint_condition);

3. 決定處理方式（刪除/更新）
   DELETE/UPDATE ...

4. 新增約束
   ALTER TABLE ... ADD CONSTRAINT ...
```
