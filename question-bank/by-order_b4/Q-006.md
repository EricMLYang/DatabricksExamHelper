## 題目內容
### 題幹
<!-- ⚠️ 保持英文原文，不要翻譯 -->
The data engineering team has a dynamic view with following definition:

```
CREATE VIEW students_vw AS
SELECT * FROM students
WHERE
    CASE
        WHEN is_member("instructors") THEN TRUE
        ELSE is_active IS FALSE
    END
```

Which statement describes the results returned by querying this view?
### 選項
<!-- ⚠️ 保持英文原文，不要翻譯 -->
- **A.** Only members of the instructors group will see the records of all students no matter if they are active or not. While users that are not members of the specified group will only see the records of inactive students
- **B.** Members of the instructors group will only see the records of active students. While users that are not members of the specified group will see null values for the records of inactive students
- **C.** Only members of the instructors group will see the records of all students no matter if they are active or not. While users that are not members of the specified group will see null values for the records of inactive students
- **D.** Members of the instructors group will only see the records of active students. While users that are not members of the specified group will only see the records of inactive students.

## 📍 考點識別
**核心技術:** Unity Catalog 動態檢視 (Dynamic View) 的列級控管
**關鍵概念:** `is_member()`、條件式過濾、行級存取控制
**題目關鍵字：**
- **dynamic view**: 以使用者或群組條件動態過濾資料
- **is_member("instructors")**: 判斷是否屬於指定群組

---

## ✅ 正解說明
### 為什麼 A 是正確答案？
`WHERE` 條件使用 `CASE`：若使用者屬於 `instructors` 群組，條件恒為 `TRUE`，所以可看到所有學生資料；否則只保留 `is_active IS FALSE` 的列，因此非群組成員只能看到**非啟用學生**的資料。

---

## ❌ 錯誤選項排除
### B
**為什麼錯誤？**
- 群組成員不是只看 active，條件為 TRUE 會看到全部。

### C
**為什麼錯誤？**
- 非群組成員不是看到 null 值，而是被 `WHERE` 過濾掉。

### D
**為什麼錯誤？**
- 群組成員不會只看到 active；他們看到所有列。

##
這段 SQL 代碼正在建立一個 **「動態安全性檢視表 (Dynamic Security View)」**。它的核心目的不是為了過濾特定的學術資料，而是為了根據 **查詢者的身份** 來決定他們能看到哪些資料。

以下是這段語法的詳細拆解：

### 1. `CREATE VIEW students_vw AS`

這行指令會建立一個名為 `students_vw` 的虛擬表（View）。往後使用者查詢這個 View 時，系統會自動執行後面的邏輯。

### 2. `SELECT * FROM students`

這部分很直覺，表示從原始的 `students` 資料表中抓取所有欄位。

### 3. `WHERE CASE ... END` (核心邏輯)

這是這段代碼最關鍵的 **存取控制 (Access Control)** 部分。它使用了 `CASE` 運算式來進行條件判斷：

* **`WHEN is_member("instructors") THEN TRUE`**
* `is_member()` 通常是資料庫（如 Databricks, Snowflake 或某些 SQL 引擎）的內建函數，用來檢查目前登入的使用者是否屬於某個群組。
* **意思：** 如果你是「講師 (instructors)」群組的一員，條件永遠為 `TRUE`。這代表你擁有 **最高權限**，可以看到 `students` 表中的 **所有原始資料**。


* **`ELSE is_active IS FALSE`**
* **意思：** 如果你 **不是** 講師（例如你是一般職員或外部系統），你只能看到 `is_active` 欄位為 `FALSE` 的學生資料。
* *註：這在邏輯上比較特別，通常是用來限制非管理員只能處理「停權」或「非活躍」的個案。*



---

### 總結這段代碼的行為

這是一個典型的 **「列級安全性 (Row-Level Security, RLS)」** 應用。

| 查詢者身份 | 能看到的資料內容 |
| --- | --- |
| **講師 (Instructors)** | `students` 表中的 **所有資料**。 |
| **非講師 (一般人)** | 僅限 **`is_active` 為 `FALSE**` 的學生。 |

### 為什麼要這樣寫？

這種寫法可以避免為不同權限的人建立多個表。所有人都查詢同一個 `students_vw`，但資料庫會根據「誰在查」來自動過濾掉不該被看見的資料。
