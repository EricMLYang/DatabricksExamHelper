## 題目內容
### 題幹
<!-- ⚠️ 保持英文原文，不要翻譯 -->
A data engineer is working with a large Delta Lake table that has deletion vectors enabled. Considering the underlying mechanics of Delta Lake and its handling of updates, which of the following statements most accurately describes how update operations behave within this table directory?
### 選項
<!-- ⚠️ 保持英文原文，不要翻譯 -->
- **A.** Update operations are ignored entirely when deletion vectors are enabled.
- **B.** Each update triggers a complete rewrite of all Parquet files that contain the affected data.
- **C.** The update operation directly modifies the existing Parquet files in place without creating new files.
- **D.** The affected rows are flagged as deleted in the deletion vectors, and the updated rows are written as new Parquet files.

# 題目解析

---

## 📍 考點識別
**核心技術:** Deletion Vectors 的更新行為
**關鍵概念:** 更新 = 標記刪除 + 寫入新檔
**題目關鍵字：**
- **deletion vectors enabled**: 啟用 DV
- **update operations**: 更新寫入機制

---

## ✅ 正解說明
### 為什麼 D 是正確答案？
啟用 deletion vectors 後，Delta 不會就地修改 Parquet 檔案。更新的列會被**標記為刪除**（寫入 DV），同時把更新後的列**寫入新的 Parquet 檔**，以維持 ACID 與檔案不可變特性。

---

## ❌ 錯誤選項排除
### A
**為什麼錯誤？**
- 更新不會被忽略，仍會生效。

### B
**為什麼錯誤？**
- 有 DV 時不需整檔重寫。

### C
**為什麼錯誤？**
- Parquet 檔案是不可變的，不支援就地修改。

---

## 🧠 記憶法
### 口訣
**「DV 更新：先標刪，再寫新。」**

### 流程圖
| 步驟 | 行為 |
|---|---|
| 1 | 將舊列標記為 deleted (DV) |
| 2 | 寫入更新後的新資料檔 |

---

## � 啟用 Deletion Vectors
### 方法一：建表時啟用
```sql
CREATE TABLE table_name (...)
USING DELTA
TBLPROPERTIES (
  'delta.enableDeletionVectors' = 'true'
);
```

### 方法二：現有表格啟用
```sql
ALTER TABLE table_name 
SET TBLPROPERTIES (
  'delta.enableDeletionVectors' = 'true'
);
```

### 方法三：全域預設啟用
```python
spark.conf.set(
  "spark.databricks.delta.properties.defaults.enableDeletionVectors", 
  "true"
)
```

### 注意事項
- **協議要求：** Delta Lake Protocol 3.0+（2023 年後版本）
- **適用場景：** 頻繁更新/刪除的大表（> 1GB）
- **維護建議：** 定期執行 `REORG TABLE` 或 `OPTIMIZE` 清理 DV

### 檢查啟用狀態
```sql
DESCRIBE DETAIL table_name;
-- 查看 properties 欄位中的 enableDeletionVectors
```
