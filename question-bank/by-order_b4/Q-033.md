# 主要差異分析

這四個儲存位置的**核心差異**在於**安全性、治理能力、以及 Unity Catalog 整合程度**:

---

## 🔍 儲存位置特性比較

### **A. Workspace files** ✅ 
- **位置**: Databricks workspace 內部
- **路徑格式**: `/Workspace/Users/...` 或 `/Workspace/Shared/...`
- **治理**: 受 workspace ACL 控制
- **Unity Catalog**: 間接整合(透過 workspace permissions)
- **安全性**: 中等(workspace-level access control)

### **B. Cloud storage** ✅
- **位置**: 外部雲端儲存(S3/ADLS/GCS)
- **路徑格式**: `s3://...`, `abfss://...`, `gs://...`
- **治理**: 可透過 External Locations + Storage Credentials
- **Unity Catalog**: **強整合**(可設定 external location)
- **安全性**: 高(cloud IAM + UC governance)

### **C. DBFS root** ❌ (已淘汰)
- **位置**: Databricks 內建檔案系統根目錄
- **路徑格式**: `dbfs:/...` (非 Unity Catalog managed)
- **治理**: **無 Unity Catalog 支援**
- **安全性**: 低(所有 cluster users 都可存取)
- **問題**: 
  - 無法進行細緻的權限控管
  - 不符合現代資料治理需求
  - 與 Unity Catalog 架構不相容

### **D. Volumes** ✅ (推薦)
- **位置**: Unity Catalog managed storage
- **路徑格式**: `/Volumes/catalog/schema/volume/...`
- **治理**: **完全整合 Unity Catalog**
- **安全性**: 最高(catalog-level, schema-level, volume-level ACLs)
- **現代化**: Databricks 最新推薦方式

---

## 🎯 關鍵差異點

| 特性 | DBFS root | 其他三者 |
|------|-----------|----------|
| Unity Catalog 支援 | ❌ 無 | ✅ 有 |
| 細緻權限控管 | ❌ 無 | ✅ 有 |
| 審計日誌 | ⚠️ 有限 | ✅ 完整 |
| 資料治理 | ❌ 不符合 | ✅ 符合 |
| 安全性等級 | 低 | 中~高 |

---

## 💡 為何淘汰 DBFS root?

```
DBFS root 的核心問題 = "所有人都能存取的共享資料夾"
```

### 具體風險:
1. **無法實施最小權限原則** - 任何能存取 cluster 的人都能讀取
2. **無審計追蹤** - 難以追蹤誰修改了 init script
3. **與 Unity Catalog 衝突** - 不在 three-level namespace 管理範圍
4. **合規性問題** - 不符合 SOC 2、ISO 27001 等標準要求

---

## 🏆 最佳實踐建議

```python
# ❌ 舊方式 (已淘汰)
dbfs:/init-scripts/setup.sh

# ✅ 推薦方式 1: Volumes (最佳)
/Volumes/prod/infra/init_scripts/setup.sh

# ✅ 推薦方式 2: Workspace files
/Workspace/Shared/init-scripts/setup.sh

# ✅ 推薦方式 3: Cloud storage with UC
s3://my-bucket/init-scripts/setup.sh  # 需先設定 External Location
```

---

## 📊 選擇建議流程圖

```
需要 init script 儲存位置?
│
├─ 需要最高治理能力? → 使用 Volumes (D)
├─ 需要與現有 S3/ADLS 整合? → 使用 Cloud storage (B)
├─ 簡單 workspace 內部管理? → 使用 Workspace files (A)
└─ 使用 DBFS root? → ❌ 不再支援 (C)
```

## 🔑 考試記憶重點

> **"DBFS root 是唯一被淘汰的選項,因為它不支援 Unity Catalog 治理架構"**

這題本質在測試你是否理解 Databricks 從**傳統檔案系統管理**轉向**Unity Catalog 統一治理**的架構演進。
