## 題目內容
### 題幹
<!-- ⚠️ 保持英文原文，不要翻譯 -->
A data engineering team has successfully established a new connection named mysql_connection in Databricks to connect to their external MySQL database. Their goal is to make the MySQL tables available and queryable through Unity Catalog by leveraging Lakehouse Federation, allowing downstream analytics teams to seamlessly access this data.

Given that the connection is already in place, the team now needs to take the next step to add the MySQL tables within Unity Catalog so that they can be queried in a governed and secure manner, consistent with their organization's data governance policies.

What is the next step the team should take to achieve this goal?

### 選項
<!-- ⚠️ 保持英文原文，不要翻譯 -->
- **A.** Create a foreign catalog in Unity Catalog using the existing mysql_connection.
- **B.** Create an external catalog with a default location defined via the existing mysql_connection.
- **C.** Create an external table referencing MySQL data through the existing mysql_connection.
- **D.** Set up a Unity Catalog metastore for MySQL using the existing mysql_connection.

## ✅ 正解說明
### 為什麼 A 是正確答案？

**Lakehouse Federation 使用 Foreign Catalog 來存取外部資料來源**：
- Connection 建立後，需要建立 Foreign Catalog
- Foreign Catalog 將外部資料庫映射到 Unity Catalog
- 使用者可以像查詢一般表格一樣查詢外部資料

#### Lakehouse Federation 架構
```
Lakehouse Federation 設定流程：

Step 1: 建立 Connection（已完成）
    ┌─────────────────┐
    │ mysql_connection│
    │ - Host          │
    │ - Port          │
    │ - Credentials   │
    └─────────────────┘
           │
           ▼
Step 2: 建立 Foreign Catalog（下一步）
    ┌─────────────────┐
    │ Foreign Catalog │
    │ - 使用 Connection│
    │ - 映射外部 DB    │
    └─────────────────┘
           │
           ▼
Step 3: 查詢外部表格
    SELECT * FROM foreign_catalog.schema.table
```

#### 建立 Foreign Catalog 語法
```sql
-- 建立 Foreign Catalog
CREATE FOREIGN CATALOG mysql_catalog
USING CONNECTION mysql_connection;

-- 查詢外部表格
SELECT * FROM mysql_catalog.database_name.table_name;

-- 設定權限
GRANT USE CATALOG ON CATALOG mysql_catalog TO analytics_team;
```

#### Foreign Catalog 優勢
```
Foreign Catalog 特性：
├── 不移動資料 → 資料留在來源系統
├── 統一治理 → 使用 Unity Catalog 權限
├── 透明存取 → 像查詢本地表格一樣
└── 即時資料 → 每次查詢取得最新資料
```

## ❌ 錯誤選項排除

### B. Create an external catalog with a default location
**為什麼錯誤？**
- **External Catalog 不是正確術語**
- Lakehouse Federation 使用的是 Foreign Catalog
- External Location 是用於存放檔案，不是連接外部資料庫

```
術語區分：
├── Foreign Catalog → 連接外部資料庫（MySQL, PostgreSQL 等）
├── External Location → 定義雲端儲存位置
└── External Table → 參照外部檔案的表格
```

### C. Create an external table referencing MySQL data
**為什麼錯誤？**
- **External Table 用於檔案存取，不是資料庫連接**
- MySQL 有多個表格，逐一建立 External Table 不實際
- Foreign Catalog 可以一次映射整個資料庫

```
Foreign Catalog vs External Table：
├── Foreign Catalog → 映射整個外部資料庫
├── External Table → 參照單一外部檔案
└── Federation 場景應使用 Foreign Catalog
```

### D. Set up a Unity Catalog metastore for MySQL
**為什麼錯誤？**
- **Metastore 是 Unity Catalog 的頂層物件，不是為單一連線建立的**
- 一個 Databricks Account 通常只有一個 Metastore
- 正確做法是在現有 Metastore 下建立 Foreign Catalog

## 🧠 記憶法
### 口訣
**「Federation 連外部，Foreign Catalog 來映射」**

### Lakehouse Federation 物件層級
```
Unity Catalog 層級（含 Federation）：

Metastore
├── Catalog (本地)
│   └── Schema
│       └── Table
├── Foreign Catalog (外部) ← Lakehouse Federation
│   └── External Schema
│       └── External Table
└── Connection (連線資訊)
```

### 支援的外部資料來源
| 資料來源 | Connection Type |
|----------|-----------------|
| MySQL | mysql |
| PostgreSQL | postgresql |
| SQL Server | sqlserver |
| Snowflake | snowflake |
| BigQuery | bigquery |
| Redshift | redshift |

### 設定流程總覽
```
Lakehouse Federation 設定步驟：
1. 建立 Connection（儲存連線資訊）
2. 建立 Foreign Catalog（映射外部資料庫）
3. 設定權限（GRANT 給使用者）
4. 查詢資料（SELECT FROM foreign_catalog.schema.table）
```
