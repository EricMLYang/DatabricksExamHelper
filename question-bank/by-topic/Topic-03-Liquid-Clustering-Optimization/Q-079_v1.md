The data architect has mandated that all tables in the Lakehouse should be configured as external (also known as "unmanaged") Delta Lake tables.

Which approach will ensure that this requirement is met?

- **B.** When configuring an external data warehouse for all table storage, leverage Databricks for all ELT.
- **C.** When data is saved to a table, make sure that a full file path is specified alongside the Delta format.
- **D.** When tables are created, make sure that the EXTERNAL keyword is used in the CREATE TABLE statement.
- **E.** When the workspace is being configured, make sure that external cloud object storage has been mounted.

# 題目解析

---

## 📍 考點識別
**核心技術:** Delta Lake 外部表（Unmanaged Tables）
**關鍵概念:** 指定資料存放位置即為外部表
**題目關鍵字：**
- **external/unmanaged**: 外部表
- **LOCATION / full path**: 指定資料位置

---

## ✅ 正解說明
### 為什麼 C 是正確答案？
外部表的關鍵是**資料檔案放在使用者指定的位置**。只要在建立表或寫入時**指定完整路徑**（或 `LOCATION`），該表就會是外部表；刪表時只刪 metadata，不刪實際資料。

範例：
```sql
CREATE TABLE external_sales
USING DELTA
LOCATION '/mnt/data/sales/';
```

或
```python
(df.write
  .format("delta")
  .mode("overwrite")
  .save("/mnt/data/sales/"))
```

---

## ❌ 錯誤選項排除
### A. 建立資料庫時用 LOCATION
**為什麼錯誤？**
- 只設定資料庫預設路徑，**不保證**所有表都是外部表

### B. 外部數倉 + ELT
**為什麼錯誤？**
- 無法保證 Databricks 表類型，描述過於籠統

### D. 使用 EXTERNAL 關鍵字
**為什麼錯誤？**
- Databricks/Delta Lake 不用 `EXTERNAL` 關鍵字

### E. 掛載外部儲存
**為什麼錯誤？**
- 只是前置作業，不決定表的類型
