## ✅ 正解說明
### 為什麼 D 是正確答案？

**Automatic Liquid Clustering 利用 Predictive Optimization 分析查詢行為**：
- 自動觀察查詢模式
- 根據實際使用情況選擇最佳叢集鍵
- 動態優化資料佈局

#### Automatic Liquid Clustering 運作原理
```
Automatic Liquid Clustering：
┌─────────────────────────────────────┐
│     Predictive Optimization         │
├─────────────────────────────────────┤
│ 1. 收集查詢歷史                     │
│ 2. 分析查詢模式                     │
│ 3. 識別常用過濾欄位                 │
│ 4. 自動選擇最佳叢集鍵               │
│ 5. 動態調整資料佈局                 │
└─────────────────────────────────────┘
```

#### 與傳統 Liquid Clustering 的差異
```
傳統 Liquid Clustering：
├── 需要手動指定 CLUSTER BY 欄位
└── 使用者決定叢集鍵

Automatic Liquid Clustering：
├── 系統自動決定叢集鍵
├── 基於查詢行為分析
└── Predictive Optimization 驅動
```

---

## ❌ 錯誤選項排除

### A. 隨機取樣選擇欄位
**為什麼錯誤？**
- **不是隨機選擇**
- 是基於查詢行為智慧選擇
- 隨機選擇無法優化效能

### B. 根據 schema 欄位順序
**為什麼錯誤？**
- **不是根據 schema 定義順序**
- 是根據實際查詢使用模式
- 欄位順序與查詢效能無直接關聯

### C. 從預定義的叢集欄位選擇
**為什麼錯誤？**
- **這是傳統 Liquid Clustering 的做法**
- Automatic 的重點是「不需要預先指定」
- 系統自動決定

```
├── 啟用 Predictive Optimization
└── 足夠的查詢歷史資料
```
