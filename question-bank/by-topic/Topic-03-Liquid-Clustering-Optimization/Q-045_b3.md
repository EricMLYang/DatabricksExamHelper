## 題目內容
### 題幹
<!-- ⚠️ 保持英文原文，不要翻譯 -->
A data engineer is analyzing a dataset of clickstream events from a high-traffic website. The dataset includes fields such as user_id, timestamp, event_type, and page_url. During a join operation between the clickstream logs and a user profile dataset (joined on user_id), the job's performance is significantly hindered due to uneven data distribution. Further analysis confirms a data skew caused by a small subset of users generating a disproportionately large number of events.

Which of the following approaches is NOT an appropriate solution to mitigate the skew in this scenario?

### 選項
<!-- ⚠️ 保持英文原文，不要翻譯 -->
- **A.** Use salting by appending a random prefix to skewed user_id values to distribute the load across partitions.
- **B.** Broadcast the skewed keys to all worker nodes to avoid shuffle during the join.
- **C.** Separate processing of skewed keys by handling high-frequency users in a dedicated job.
- **D.** Repartition the clickstream dataset on user_id to increase the number of partitions before the join.

# 題目解析

---

## 📍 考點識別
**核心技術:** Data Skew 處理
**關鍵概念:** Broadcast 限制、Salting 技術
**題目關鍵字：**
- **data skew**: 資料傾斜
- **NOT an appropriate solution**: 不是合適的解決方案
- **broadcast**: 廣播

---

## ✅ 正解說明
### 為什麼 B 是不適當的方案（正確答案）？

**Broadcast 不能解決 skewed keys 的問題**：
- Broadcast 是廣播「小表」，不是「特定 keys」
- 如果 skewed keys 的資料量大，廣播會造成記憶體壓力
- Broadcast 不會改變資料傾斜的分布

#### 為什麼 Broadcast 無效
```
Data Skew 問題：
user_id = "A" → 100萬筆事件
user_id = "B" → 10筆事件
user_id = "C" → 15筆事件

Broadcast skewed keys 的問題：
├── 「Broadcast keys」概念不存在
├── Broadcast 是廣播整個小表
├── 即使廣播，傾斜的資料仍在同一分區
└── 不會解決處理不均的問題
```

---

## ❌ 其他選項為何正確

### A. Salting（加鹽）
**這是有效的解決方案**：
- 在 skewed key 加上隨機前綴
- 資料分散到多個分區
- 減少單一分區的負擔

```python
# Salting 範例
from pyspark.sql.functions import concat, lit, rand

# 對傾斜的 key 加鹽
df_salted = df.withColumn(
    "salted_user_id",
    concat(col("user_id"), lit("_"), (rand() * 10).cast("int"))
)
```

### C. 分離處理傾斜 keys
**這是有效的解決方案**：
- 將高頻使用者單獨處理
- 避免影響其他正常資料

### D. Repartition 增加分區數
**這是有效的解決方案**：
- 增加分區可以提高並行度
- 雖然不能完全解決傾斜，但能緩解

---

## 🧠 記憶法
### 口訣
**「Broadcast 廣播小表，Skew 要用 Salt」**

### Data Skew 解決方案比較
| 方案 | 適用情境 | 效果 |
|------|----------|------|
| Salting | 嚴重傾斜 | ⭐⭐⭐ 最有效 |
| 分離處理 | 已知傾斜 keys | ⭐⭐⭐ 有效 |
| Repartition | 輕微傾斜 | ⭐⭐ 緩解 |
| Broadcast | 小表 Join | ❌ 不解決傾斜 |
