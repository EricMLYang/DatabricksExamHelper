## 📍 考點識別
**核心技術:** Delta Lake OPTIMIZE 指令

**題目關鍵字：**
- **OPTIMIZE**: 檔案壓縮指令

## ✅ 正解說明
### 為什麼 B 是正確答案？

**OPTIMIZE 的預設目標檔案大小是 1 GB (1024 MB)**：
- 預設值：1073741824 bytes = 1 GB
- 這個大小經過優化，平衡讀取效能和並行度
- 可以透過參數調整

#### OPTIMIZE 運作原理
```
OPTIMIZE 執行流程：
小檔案群組                    壓縮後
┌────┐┌────┐┌────┐         ┌──────────────┐
│10MB││20MB││30MB│   ───►  │    1 GB      │
└────┘└────┘└────┘         └──────────────┘
┌────┐┌────┐               ┌──────────────┐
│50MB││15MB│         ───►  │    1 GB      │
└────┘└────┘               └──────────────┘
```

#### 預設參數
```sql
-- 預設目標檔案大小
-- spark.databricks.delta.optimize.maxFileSize = 1073741824 (1 GB)

-- 執行 OPTIMIZE
OPTIMIZE my_table;

-- 查看 OPTIMIZE 結果
DESCRIBE DETAIL my_table;
```

#### 為什麼是 1 GB？
```
1 GB 檔案大小的優勢：
├── 讀取效能 → 減少檔案列舉時間
├── 並行度 → 足夠大以利用 Parquet 特性
├── 記憶體效率 → 適合大多數 Cluster 配置
└── 壓縮比 → 良好的壓縮效果
```

## ❌ 錯誤選項排除

### A. 128 MB
**為什麼錯誤？**
- **128 MB 是 Auto Optimize 的預設大小**
- 不是手動 OPTIMIZE 的預設值
- 兩者是不同的功能

```
重要區分：
├── OPTIMIZE (手動) → 預設 1 GB
├── Auto Optimize → 預設 128 MB
└── 兩者服務不同場景
```

### C. 256 MB
**為什麼錯誤？**
- **256 MB 不是預設值**
- 這是常見的 Parquet 檔案大小，但不是 OPTIMIZE 預設
- 可能與其他系統混淆

### D. 512 MB
**為什麼錯誤？**
- **512 MB 不是預設值**
- 雖然是 2 的冪次，但不是 OPTIMIZE 的預設設定
- 可能與其他系統混淆

## 🧠 記憶法
### 口訣
**「手動 OPTIMIZE 一個 G，Auto 只要 128 M」**

### 檔案大小設定比較
| 功能 | 預設大小 | 參數 |
|------|----------|------|
| OPTIMIZE | 1 GB | `delta.optimize.maxFileSize` |
| Auto Optimize | 128 MB | `delta.autoOptimize.maxFileSize` |
| Liquid Clustering | 1 GB | 自動調整 |

### OPTIMIZE 相關參數
```sql
-- 調整目標檔案大小
ALTER TABLE my_table
SET TBLPROPERTIES (
    'delta.targetFileSize' = '512mb'
);

-- 或使用 Spark 參數
SET spark.databricks.delta.optimize.maxFileSize = 536870912;  -- 512 MB
```

### 常見數字記憶
```
Delta Lake 常見大小數字：
├── OPTIMIZE 預設 → 1 GB (1024 MB)
├── Auto Optimize 預設 → 128 MB
├── VACUUM 預設保留 → 168 小時 (7 天)
└── 小檔案問題閾值 → 通常 < 100 MB
```

### OPTIMIZE 最佳實踐
```
何時執行 OPTIMIZE？
├── 大量小檔案產生後
├── 批次寫入完成後
├── 排程定期執行
└── 查詢效能下降時
```
