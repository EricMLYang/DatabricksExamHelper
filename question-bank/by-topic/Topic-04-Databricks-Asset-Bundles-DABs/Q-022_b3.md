What is the recommended method for authenticating DABs to the target Databricks workspace in this scenario?

## ✅ 正解說明
### 為什麼 C 是正確答案？

**OAuth Token Federation 的優勢**：
- **無需管理 Databricks 密鑰**
- **利用 GitHub 的 OIDC 機制**
- **短期權杖，自動輪換**
- **最安全的 CI/CD 認證方式**

#### OAuth Token Federation 運作原理
```
GitHub Actions ─── OIDC Token ───► Databricks
                                        │
                                        ▼
                               Service Principal
                                        │
                                        ▼
                                 短期 Access Token
```

#### 設定流程
```yaml
# GitHub Actions 設定範例
jobs:
  deploy:
    runs-on: ubuntu-latest
    permissions:
      id-token: write  # 需要 OIDC 權限
    steps:
      - name: Authenticate to Databricks
        uses: databricks/setup-cli@main
        with:
          # 使用 Token Federation
          # 無需儲存任何密鑰
```

#### 為什麼這是最佳實踐？
```
OAuth Token Federation 優勢：
├── 無密鑰管理 → 降低洩漏風險
├── 短期權杖 → 自動過期
├── 自動輪換 → 無需手動更新
├── 審計追蹤 → 可追溯來源
└── 最小權限 → Service Principal 範圍限制
```

## ❌ 錯誤選項排除

### A. Personal Access Token for a Databricks service principal
**為什麼錯誤？**
- **PAT 需要手動管理和輪換**
- 需要在 GitHub Secrets 中儲存 PAT
- 如果洩漏，風險較高
- 不如 OAuth Federation 安全

```
PAT 缺點：
├── 長期有效 → 洩漏風險高
├── 需手動輪換 → 管理負擔
└── 需儲存密鑰 → 增加暴露面
```

### B. Personal Access Token for an administrator user
**為什麼錯誤？**
- **使用管理員帳號是最差的做法**
- 違反最小權限原則
- 如果洩漏，影響範圍最大
- 不符合企業安全規範

```
管理員 PAT 風險：
├── 權限過大 → 可存取所有資源
├── 無法限制範圍 → 違反最小權限
└── 洩漏後果嚴重 → 整個 Workspace 暴露
```

### D. OAuth client secret for a Databricks service principal
**為什麼錯誤？**
- **OAuth Client Secret 仍需管理密鑰**
- 需要在 GitHub Secrets 中儲存 Client Secret
- 比 PAT 好，但不如 Token Federation
- 無法利用 GitHub OIDC 的優勢

```
OAuth Client Secret vs Token Federation：
├── Client Secret → 仍需儲存密鑰
├── Token Federation → 無密鑰管理
└── 推薦 → Token Federation
```

## 🧠 記憶法
### 口訣
**「CI/CD 認證，Federation 最安全」**

### 認證方式比較表
| 方式 | 密鑰管理 | 安全性 | 推薦度 |
|------|----------|--------|--------|
| OAuth Token Federation | 無 | ⭐⭐⭐ | ✅ 最推薦 |
| OAuth Client Secret | 需要 | ⭐⭐ | 可接受 |
| Service Principal PAT | 需要 | ⭐ | 不推薦 |
| Admin User PAT | 需要 | ❌ | 禁止 |

### 選擇指南
```
如何選擇認證方式？
├── 有 OIDC 支援？（GitHub/Azure/GCP）
│   └── 是 → OAuth Token Federation
├── 無 OIDC 支援？
│   └── 使用 OAuth Client Secret
└── 永遠不要使用管理員 PAT
```
