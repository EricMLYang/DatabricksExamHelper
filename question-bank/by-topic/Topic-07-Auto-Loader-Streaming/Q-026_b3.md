# 題目解析

## 📍 考點識別
**核心技術:** Stream-Static Join 行為
**關鍵概念:** Delta Lake 版本保證、Microbatch 處理
**題目關鍵字：**
- **Stream-Static join**: 串流與靜態表的 Join
- **static Delta table**: 靜態 Delta 表格
- **microbatch**: 微批次處理

---

## ✅ 正解說明
### 為什麼 A 是正確答案？

**Delta Lake 的核心保證**：
- **每次 microbatch 查詢時都返回最新版本**
- 不需要手動刷新
- 自動獲取 Delta 表的最新快照

#### Stream-Static Join 運作原理
```
Stream-Static Join 執行流程：

Streaming Data                Static Delta Table
     │                              │
     ▼                              ▼
 Microbatch 1  ─────────►  查詢 Delta Table (v1)
     │                              │
     ▼                              │ (Delta Table 更新到 v2)
 Microbatch 2  ─────────►  查詢 Delta Table (v2)
     │                              │
     ▼                              │ (Delta Table 更新到 v3)
 Microbatch 3  ─────────►  查詢 Delta Table (v3)
```

#### 為什麼這是 Delta Lake 的優勢？
```python
# Stream-Static Join 範例
stream_df = spark.readStream.format("delta").load("/path/to/stream")
static_df = spark.read.format("delta").load("/path/to/static")

# 每個 microbatch 會自動獲取 static_df 的最新版本
result = stream_df.join(static_df, "key")

result.writeStream \
    .format("delta") \
    .start("/path/to/output")
```

#### Delta Lake 版本保證
```
Delta Lake 特性：
├── ACID 事務 → 讀取一致性
├── 版本快照 → 每次查詢獲取最新版本
├── 無需手動刷新 → 自動更新
└── 效能優化 → 只讀取變更部分
```

---

## ❌ 錯誤選項排除

### B. 只在第一個 microbatch 返回最新版本，之後快取
**為什麼錯誤？**
- **Delta Lake 不會快取靜態表的舊版本**
- 每個 microbatch 都會重新查詢
- 這是 Delta Lake 的核心保證

```
錯誤認知：
├── 不是「快取第一次結果」
├── 而是「每次都查詢最新」
└── 這是 Delta Lake 的優勢
```

### C. 需要 REFRESH TABLE 命令
**為什麼錯誤？**
- **Delta Lake 不需要手動刷新**
- `REFRESH TABLE` 用於外部表格，不是 Delta
- Delta 自動提供最新版本

```
REFRESH TABLE 用途：
├── 用於外部（非 Delta）表格
├── 刷新 metastore 的 metadata
└── Delta 表格不需要此命令
```

### D. 靜態表必須小到可以廣播
**為什麼錯誤？**
- **Stream-Static Join 不要求表格大小**
- 廣播是優化策略，不是必要條件
- Spark 會根據情況選擇 Join 策略

```
Join 策略選擇：
├── 小表 → 可能使用 Broadcast Join
├── 大表 → 使用 Sort-Merge Join
└── 大小不影響功能，只影響效能
```

## 🧠 記憶法
### 口訣
**「Delta 保證最新，每批都查詢」**

### Stream-Static vs Stream-Stream 比較
| 特性 | Stream-Static | Stream-Stream |
|------|--------------|---------------|
| 靜態表版本 | 每批查最新 | N/A |
| 狀態管理 | 無狀態 | 有狀態 |
| 水印需求 | 不需要 | 需要 |
| 記憶體使用 | 較低 | 較高 |

### 使用場景
```
Stream-Static Join 適用於：
├── 維度表 Join（如客戶資訊）
├── 查找表 Join（如產品目錄）
├── 配置表 Join（如價格規則）
└── 任何「慢變」參考資料
```

### 實作範例
```python
# 典型 Stream-Static Join 場景
# 串流：交易資料
# 靜態：客戶資訊

transactions_stream = spark.readStream.format("delta").load("/transactions")
customers_static = spark.read.format("delta").load("/customers")

enriched = transactions_stream.join(
    customers_static,
    transactions_stream.customer_id == customers_static.id
)

# 客戶資訊更新後，下一個 microbatch 會自動使用新資料
```
