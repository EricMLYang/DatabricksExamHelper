## 題目內容
### 題幹
<!-- ⚠️ 保持英文原文，不要翻譯 -->
A data engineer has implemented the following streaming ingestion code using Databricks Auto Loader:

```python
spark.readStream \
     .format("cloudFiles") \
     .schema(expected_schema) \
     .option("cloudFiles.format", "json") \
     .option("cloudFiles.schemaEvolutionMode", "failOnNewColumns") \
     .load("s3://vendor/raw/sales/json/") \
    .writeStream \
     .option("checkpointLocation", "s3://vendor/checkpoints/sales") \
     .start("sales_table")
```

What is the expected behavior of this streaming job if a new column appears in the incoming JSON files that is not part of the original schema?

### 選項
<!-- ⚠️ 保持英文原文，不要翻譯 -->
- **A.** The stream fails and will not restart unless the schema is manually updated or the problematic data file is removed.
- **B.** The stream fails temporarily but continues by ignoring the new columns without schema update.
- **C.** The stream fails, but it automatically restarts after updating the schema with the new columns.
- **D.** The stream fails, and all new columns are saved in a rescued data column for later processing.

## 📍 考點識別
**核心技術:** Auto Loader Schema Evolution Modes
**關鍵概念:** failOnNewColumns 模式行為
**題目關鍵字：**
- **schemaEvolutionMode**: Schema 演化模式
- **failOnNewColumns**: 遇到新欄位時失敗
- **new column appears**: 出現新欄位的情境

---

## ✅ 正解說明
### 為什麼 A 是正確答案？

**`failOnNewColumns` 模式設計用於嚴格的 Schema 控制**：
- **偵測到新欄位時立即失敗**
- **不會自動重啟**
- **需要人工介入處理**

#### failOnNewColumns 行為流程
```
failOnNewColumns 執行流程：
    新檔案到達
        │
        ▼
    偵測 Schema
        │
    ┌───┴───┐
    │ 新欄位？│
    └───┬───┘
    是  │  否
    │   │
    ▼   ▼
  失敗  繼續處理
    │
    ▼
  等待人工處理：
  ├── 更新 Schema 定義
  └── 或移除問題檔案
```

#### 為什麼這樣設計？
```
嚴格 Schema 控制的價值：
├── 防止 Schema Drift（Schema 漂移）
├── 確保資料品質一致性
├── 強制人工審核新欄位
└── 避免意外的資料結構變更
```

#### 處理方式
```python
# 發現新欄位後的處理步驟：

# 方法 1: 更新 Schema 定義
new_schema = StructType([
    StructField("existing_col", StringType()),
    StructField("new_col", StringType())  # 新增欄位
])

spark.readStream \
    .format("cloudFiles") \
    .schema(new_schema)  # 使用更新後的 Schema
    ...

# 方法 2: 移除問題檔案
# 從 S3 刪除包含新欄位的檔案
# 然後重啟串流
```

## ❌ 錯誤選項排除

### B. 失敗後繼續，忽略新欄位
**為什麼錯誤？**
- **`failOnNewColumns` 會完全停止**
- 不會忽略新欄位繼續處理
- 這種行為是 `rescue` 或 `addNewColumns` 模式

```
failOnNewColumns ≠ 忽略：
├── 偵測到新欄位 → 完全停止
├── 不會自動跳過
└── 必須人工處理
```

### C. 自動更新 Schema 並重啟
**為什麼錯誤？**
- **`failOnNewColumns` 不會自動更新 Schema**
- 這種行為是 `addNewColumns` 模式
- `failOnNewColumns` 設計目的就是防止自動變更

```
schemaEvolutionMode 比較：
├── failOnNewColumns → 失敗，等待人工處理
├── addNewColumns → 自動加入新欄位
└── rescue → 存入 _rescued_data 欄位
```

### D. 新欄位存入 rescued data column
**為什麼錯誤？**
- **這是 `rescue` 模式的行為**
- `failOnNewColumns` 不會使用 rescued data
- 它直接失敗，不做任何資料處理

```python
# rescue 模式的行為（不是本題）
.option("cloudFiles.schemaEvolutionMode", "rescue")
# 新欄位會存入 _rescued_data 欄位

# failOnNewColumns 的行為（本題）
.option("cloudFiles.schemaEvolutionMode", "failOnNewColumns")
# 直接失敗，不處理任何資料
```

## 🧠 記憶法
### 口訣
**「failOnNewColumns，遇新即停，人工處理」**

### Schema Evolution Modes 比較表
| 模式 | 遇到新欄位行為 | 適用場景 |
|------|---------------|----------|
| `failOnNewColumns` | 失敗停止 | 嚴格 Schema 控制 |
| `addNewColumns` | 自動加入 | 彈性 Schema |
| `rescue` | 存入 _rescued_data | 需要審查新欄位 |
| `none` | 忽略新欄位 | 只需固定欄位 |

### 選擇指南
```
如何選擇 schemaEvolutionMode？

需要嚴格控制 Schema？
├── 是 → failOnNewColumns
└── 否 → 繼續判斷

需要自動適應新欄位？
├── 是 → addNewColumns
└── 否 → 繼續判斷

需要審查新欄位再決定？
├── 是 → rescue
└── 否 → none
```

### 記憶技巧
```
模式名稱暗示行為：
├── fail + OnNewColumns = 遇到新欄位就失敗
├── add + NewColumns = 加入新欄位
├── rescue = 救援（存起來）
└── none = 什麼都不做（忽略）
```
