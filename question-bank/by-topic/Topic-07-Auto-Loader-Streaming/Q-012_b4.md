## 題目內容
### 題幹
<!-- ⚠️ 保持英文原文，不要翻譯 -->
The data engineering team has a large Delta Lake table named 'user_posts' which is partitioned over the 'year' column. The table is used as an input streaming source in a streaming job. The streaming query is displayed below with a blank:

```
spark.readStream
       .table("user_posts")
       ________________
       .groupBy("post_category", "post_date")
       .agg(
           count("psot_id").alias("posts_count"),
           sum("likes").alias("total_likes"))
    .writeStream
       .option("checkpointLocation", "dbfs:/path/checkpoint")
       .table("psots_stats")
```

They want to remove previous 2 years data from the table without breaking the append-only requirement of streaming sources.

Which option correctly fills in the blank to enable stream processing from the table after deleting the partitions?
### 選項
<!-- ⚠️ 保持英文原文，不要翻譯 -->
- **A.** .window("year", "INTERVAL 2 YEARS")
- **B.** .option("ignoreDeletes", True)
- **C.** .withWatermark("year", "INTERVAL 2 YEARS")
- **D.** .option("ignoreDeletes", "year")

# 題目解析

---

## 📍 考點識別
**核心技術:** Delta Streaming source 的刪除行為處理
**關鍵概念:** `ignoreDeletes` 允許分割區刪除後仍可串流
**題目關鍵字：**
- **partitioned**: 分割區刪除
- **append-only requirement**: 串流來源限制

---

## ✅ 正解說明
### 為什麼 B 是正確答案？
對 Delta table 做分割區刪除會被視為 delete，會破壞 streaming source 的 append-only 假設。設定 `ignoreDeletes` 可讓 streaming 查詢在**忽略刪除事件**的情況下繼續處理。

```python
spark.readStream
  .table("user_posts")
  .option("ignoreDeletes", True)
```

---

## ❌ 錯誤選項排除
### A. window
**為什麼錯誤？**
- `window` 是聚合窗口，與刪除容忍無關。

### C. withWatermark
**為什麼錯誤？**
- watermark 控制延遲資料，不是處理 delete。

### D. ignoreDeletes with column
**為什麼錯誤？**
- `ignoreDeletes` 只接受布林值，不能填欄位名稱。

---

## 🧠 記憶法
### 口訣
**「刪除不想管，ignoreDeletes。」**

### 比較表
| 需求 | 正確設定 |
|---|---|
| 忽略刪除事件 | `option("ignoreDeletes", True)` |
| 延遲資料處理 | `withWatermark` |
