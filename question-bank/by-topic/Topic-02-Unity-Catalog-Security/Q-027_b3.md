## 題目內容
### 題幹
<!-- ⚠️ 保持英文原文，不要翻譯 -->
The data engineering team has a Delta Lake table created with following query:

```sql
CREATE TABLE customers_clone
LOCATION 'dbfs:/mnt/backup'
AS SELECT * FROM customers
```

A data engineer wants to drop the table with the following query:

```sql
DROP TABLE customers_clone
```

Which statement describes the result of running this drop command?

### 選項
<!-- ⚠️ 保持英文原文，不要翻譯 -->
- **A.** Only the table's metadata will be deleted from the catalog, while the data files will be kept in the storage.
- **B.** The table will not be dropped until VACUUM command is run.
- **C.** Both the table's metadata and the data files will be deleted.
- **D.** An error will occur as the table is shallowly cloned from the customers table.

# 題目解析

---

## 📍 考點識別
**核心技術:** Managed Table vs External Table
**關鍵概念:** DROP TABLE 行為、LOCATION 子句影響
**題目關鍵字：**
- **LOCATION clause**: 指定外部儲存位置
- **DROP TABLE**: 刪除表格
- **metadata vs data files**: Metadata 與資料檔案

---

## ✅ 正解說明
### 為什麼 A 是正確答案？

**使用 LOCATION 建立的是 External (Unmanaged) Table**：
- DROP TABLE 只刪除 metadata
- 資料檔案保留在指定位置
- 這是外部表的核心特性

#### External Table vs Managed Table
```
DROP TABLE 行為比較：

External Table (有 LOCATION)：
├── DROP TABLE 執行
├── Metadata 刪除 ✅
├── 資料檔案保留 ✅
└── 儲存路徑不受影響

Managed Table (無 LOCATION)：
├── DROP TABLE 執行
├── Metadata 刪除 ✅
├── 資料檔案刪除 ✅
└── 儲存空間釋放
```

#### 程式碼分析
```sql
-- 這是 External Table（因為有 LOCATION）
CREATE TABLE customers_clone
LOCATION 'dbfs:/mnt/backup'  -- 👈 關鍵：指定了外部位置
AS SELECT * FROM customers

-- DROP TABLE 只移除 catalog 中的記錄
DROP TABLE customers_clone

-- 結果：
-- 1. Catalog 中的 table 定義消失
-- 2. dbfs:/mnt/backup 中的資料仍然存在
```

#### 為什麼這樣設計？
```
External Table 設計理念：
├── 資料與 metadata 分離管理
├── 資料可能被多個系統共用
├── 刪除 table 不應影響原始資料
└── 提供更靈活的資料生命週期管理
```

---

## ❌ 錯誤選項排除

### B. 需要 VACUUM 才能 DROP
**為什麼錯誤？**
- **DROP TABLE 與 VACUUM 是獨立操作**
- VACUUM 用於清理舊版本檔案，不是 DROP 的前置條件
- DROP TABLE 可以直接執行

```
VACUUM vs DROP TABLE：
├── VACUUM → 清理舊版本檔案
├── DROP TABLE → 刪除 table 定義
└── 兩者無依賴關係
```

### C. metadata 和資料檔案都會刪除
**為什麼錯誤？**
- **這是 Managed Table 的行為**
- External Table（有 LOCATION）不會刪除資料
- 題目中明確有 LOCATION 子句

```
判斷 Table 類型：
├── 有 LOCATION → External → 資料保留
└── 無 LOCATION → Managed → 資料刪除
```

### D. 因為是 shallow clone 會報錯
**為什麼錯誤？**
- **這不是 Clone 語法**
- `CREATE TABLE ... AS SELECT` 是完整複製（CTAS）
- Clone 語法是 `CREATE TABLE ... CLONE`

```sql
-- 這是 CTAS（完整複製），不是 Clone
CREATE TABLE customers_clone
LOCATION 'dbfs:/mnt/backup'
AS SELECT * FROM customers

-- Clone 語法範例
CREATE TABLE customers_clone
SHALLOW CLONE customers
LOCATION 'dbfs:/mnt/backup'
```

## 🧠 記憶法
### 口訣
**「有 LOCATION 是外部，DROP 只刪 metadata」**

### Managed vs External Table 比較
| 特性 | Managed Table | External Table |
|------|--------------|----------------|
| LOCATION | 無（系統管理） | 有（使用者指定） |
| DROP 行為 | 刪除 metadata + 資料 | 只刪除 metadata |
| 資料位置 | Metastore 管理 | 使用者控制 |
| 適用場景 | 一般資料表 | 共享資料、外部資料 |

### 判斷 Table 類型
```
如何判斷 Table 類型？

建立語法中有 LOCATION？
├── 是 → External Table
│   └── DROP 後資料保留
└── 否 → Managed Table
    └── DROP 後資料刪除
```

### External Table 使用場景
```
適合使用 External Table 的情境：
├── 多個 Table 共用同一資料源
├── 資料由外部系統管理
├── 需要保護資料不被誤刪
└── 跨 Workspace 共享資料
```
