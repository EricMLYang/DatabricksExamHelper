## 題目內容
### 題幹
<!-- ⚠️ 保持英文原文，不要翻譯 -->
The data engineering team has a secret scope named 'DataOps-Prod' that contains all secrets needed by DataOps engineers in a production workspace.

Which of the following is the minimum permission required for the DataOps engineers to use the secrets in this scope?

### 選項
<!-- ⚠️ 保持英文原文，不要翻譯 -->
- **A.** MANAGE permission on the "DataOps-Prod" scope
- **B.** READ permission on each secret in the "DataOps-Prod" scope
- **C.** READ permission on the "DataOps-Prod" scope
- **D.** MANAGE permission on each secret in the "DataOps-Prod" scope

# 題目解析

---

## 📍 考點識別
**核心技術:** Databricks Secrets 權限管理
**關鍵概念:** Secret Scope 權限層級
**題目關鍵字：**
- **minimum permission**: 最小權限
- **use the secrets**: 使用密鑰
- **scope**: 範圍

---

## ✅ 正解說明
### 為什麼 C 是正確答案？

**READ permission 在 scope 層級即可使用所有 secrets**：
- 權限設定在 scope 層級，不是個別 secret 層級
- READ 是使用 secrets 的最小權限
- 可以讀取 scope 內所有 secrets

#### Secret 權限層級
```
Secret Scope 權限層級（由低到高）：
├── READ → 讀取 secrets、列出可用 secrets
├── WRITE → 包含上述 + 寫入 secrets
└── MANAGE → 包含上述 + 修改 ACLs
```

#### 重要概念
```
Secret 權限模型：
├── 權限設定在 scope 層級
├── 不是在個別 secret 層級
├── 高權限包含低權限的所有能力
└── READ 足夠用於讀取和使用 secrets
```

---

## ❌ 錯誤選項排除

### A. MANAGE permission on scope
**為什麼錯誤？**
- **權限過高**
- MANAGE 用於管理 ACLs，超過使用 secrets 的需求

### B. READ permission on each secret
**為什麼錯誤？**
- **權限設定在 scope 層級，不是 secret 層級**
- Databricks 不支援個別 secret 的權限設定

### D. MANAGE permission on each secret
**為什麼錯誤？**
- **權限過高且設定層級錯誤**
- 不需要 MANAGE 權限
- 權限不在個別 secret 層級設定

---

## 🧠 記憶法
### 口訣
**「Scope 定權限，READ 能使用，MANAGE 管 ACL」**

### Secret 權限對照
| 權限 | 能力 |
|------|------|
| READ | 讀取、列出 secrets |
| WRITE | 包含 READ + 寫入 secrets |
| MANAGE | 包含 WRITE + 管理 ACLs |
