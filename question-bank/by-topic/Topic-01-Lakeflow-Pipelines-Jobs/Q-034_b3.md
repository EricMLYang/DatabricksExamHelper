## 題目內容
### 題幹
<!-- ⚠️ 保持英文原文，不要翻譯 -->
A data engineer needs to programmatically extract the data quality results of a LDP pipeline from the associated event log table.

Which of the following code snippets can the data engineer use to achieve this task?

### 選項
<!-- ⚠️ 保持英文原文，不要翻譯 -->
- **A.**
```sql
SELECT data_quality
FROM catalog.schema.event_log
WHERE event_type = 'metrics'
```
- **B.**
```sql
SELECT expectations
FROM catalog.schema.event_log
WHERE event_type = 'flow_progress'
```
- **C.**
```sql
SELECT details:flow_progress.data_quality.expectations
FROM catalog.schema.event_log
WHERE event_type = 'flow_progress'
```
- **D.**
```sql
SELECT expectations
FROM catalog.schema.event_log
WHERE event_type = 'metrics'
```

# 題目解析

---

## 📍 考點識別
**核心技術:** Lakeflow DLP Event Log 結構
**關鍵概念:** event_type、details 欄位的 JSON 結構
**題目關鍵字：**
- **event log table**: 事件日誌表格
- **data quality results**: 資料品質結果
- **programmatically extract**: 程式化提取

---

## ✅ 正解說明
### 為什麼 C 是正確答案？

**DLP Event Log 的資料品質結果存在特定的 JSON 路徑**：
- 事件類型：`flow_progress`
- JSON 路徑：`details:flow_progress.data_quality.expectations`

#### Event Log 結構
```
DLP Event Log 表格結構：

┌───────────────┬────────────────────────────────────────────┐
│  event_type   │                 details                    │
├───────────────┼────────────────────────────────────────────┤
│ flow_progress │ {                                          │
│               │   "flow_progress": {                       │
│               │     "data_quality": {                      │
│               │       "expectations": [...],               │
│               │       "dropped_records": 0                 │
│               │     }                                      │
│               │   }                                        │
│               │ }                                          │
├───────────────┼────────────────────────────────────────────┤
│ metrics       │ { "metrics": {...} }                       │
├───────────────┼────────────────────────────────────────────┤
│ user_action   │ { "user_action": {...} }                   │
└───────────────┴────────────────────────────────────────────┘
```

#### 完整查詢範例
```sql
-- 查詢資料品質 expectations
SELECT
    timestamp,
    details:flow_progress.data_quality.expectations AS expectations,
    details:flow_progress.data_quality.dropped_records AS dropped_records
FROM catalog.schema.event_log
WHERE event_type = 'flow_progress'
  AND details:flow_progress.data_quality IS NOT NULL;

-- expectations 結果範例：
-- [
--   {"name": "valid_id", "dataset": "silver_sales", "passed": true, "failed": 0},
--   {"name": "recent_sales", "dataset": "silver_sales", "passed": false, "failed": 10}
-- ]
```

#### JSON 路徑語法說明
```
Databricks JSON 路徑語法：
column_name:json_key.nested_key.deeper_key

範例：
details:flow_progress.data_quality.expectations
   │          │              │           │
   │          │              │           └── 最內層 key
   │          │              └── 中層 key
   │          └── 外層 key
   └── 欄位名稱
```

## ❌ 錯誤選項排除

### A. SELECT data_quality ... WHERE event_type = 'metrics'
**為什麼錯誤？**
- **`data_quality` 不是頂層欄位**
- 資料品質在 `details` 欄位的 JSON 結構中
- `metrics` 事件類型不包含資料品質資訊

```
錯誤原因：
├── data_quality 不是欄位名稱
├── 需要用 JSON 路徑存取
└── metrics 事件不含 data_quality
```

### B. SELECT expectations ... WHERE event_type = 'flow_progress'
**為什麼錯誤？**
- **`expectations` 不是頂層欄位**
- 必須用完整 JSON 路徑：`details:flow_progress.data_quality.expectations`
- 雖然 event_type 正確，但欄位存取方式錯誤

```sql
-- 錯誤：直接存取不存在的欄位
SELECT expectations FROM event_log  -- 錯誤！

-- 正確：使用 JSON 路徑
SELECT details:flow_progress.data_quality.expectations FROM event_log  -- 正確！
```

### D. SELECT expectations ... WHERE event_type = 'metrics'
**為什麼錯誤？**
- **event_type 錯誤**：資料品質在 `flow_progress` 不是 `metrics`
- **欄位存取錯誤**：需要用 JSON 路徑
- 兩個錯誤的組合

## 🧠 記憶法
### 口訣
**「flow_progress 存品質，details JSON 路徑查」**

### Event Log event_type 類型
| event_type | 內容 |
|------------|------|
| `flow_progress` | Pipeline 執行進度、資料品質 |
| `metrics` | 效能指標 |
| `user_action` | 使用者操作 |
| `cluster_resources` | 叢集資源資訊 |

### 資料品質 JSON 結構
```
details:flow_progress.data_quality
├── expectations (array)
│   ├── name: 規則名稱
│   ├── dataset: 資料集名稱
│   ├── passed: 是否通過
│   └── failed: 失敗數量
└── dropped_records: 被丟棄的記錄數
```

### 常用查詢範例
```sql
-- 查詢所有失敗的 expectations
SELECT
    details:flow_progress.data_quality.expectations AS exp
FROM catalog.schema.event_log
WHERE event_type = 'flow_progress'
  AND details:flow_progress.data_quality.dropped_records > 0;

-- 展開 expectations array
SELECT
    explode(details:flow_progress.data_quality.expectations) AS expectation
FROM catalog.schema.event_log
WHERE event_type = 'flow_progress';
```
