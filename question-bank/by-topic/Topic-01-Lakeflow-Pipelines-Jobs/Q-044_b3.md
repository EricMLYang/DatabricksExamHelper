## 題目內容
### 題幹
<!-- ⚠️ 保持英文原文，不要翻譯 -->
A data engineer has a Job with multiple tasks that takes more than 2 hours to complete. In the last run, the final task unexpectedly failed.

Which of the following actions can the data engineer perform to complete this run while minimizing the execution time?

### 選項
<!-- ⚠️ 保持英文原文，不要翻譯 -->
- **A.** They need to delete the failed Run, and start a new Run for the Job.
- **B.** They can keep the failed Run, and simply start a new Run for the Job.
- **C.** They can rerun this Job Run to execute all the tasks.
- **D.** They can repair this Job Run so only the failed tasks will be re-executed.

## 📍 考點識別
**核心技術:** Databricks Jobs Repair 功能

- **failed task**: 失敗的任務

---

## ✅ 正解說明
### 為什麼 D 是正確答案？

**Repair Run 只重新執行失敗的任務**：
- 成功的任務不會重跑
- 大幅減少恢復時間
- 保留原本 Run 的 context

#### Repair Run 流程
```
原始 Run（失敗）：
Task 1: ✅ 成功 (30分鐘)
Task 2: ✅ 成功 (45分鐘)
Task 3: ✅ 成功 (30分鐘)
Task 4: ❌ 失敗 (15分鐘)

Repair Run：
Task 1: 跳過（已成功）
Task 2: 跳過（已成功）
Task 3: 跳過（已成功）
Task 4: ▶️ 重新執行

時間比較：
├── 完整重跑 → 2小時+
└── Repair → 只需執行 Task 4
```

---

## ❌ 錯誤選項排除

### A. 刪除失敗 Run，啟動新 Run
**為什麼錯誤？**
- **會重跑所有任務，浪費時間**
- 已成功的任務會重複執行

### B. 保留失敗 Run，啟動新 Run
**為什麼錯誤？**
- **同樣會重跑所有任務**
- 不是最佳化的做法

### C. 重新執行所有任務
**為什麼錯誤？**
- **同樣浪費時間**
- 沒有利用 Repair 功能

---

## 🧠 記憶法
### 口訣
**「Repair 修失敗，成功不重來」**

### Repair vs Rerun
| 操作 | 執行範圍 | 適用場景 |
|------|----------|----------|
| Repair | 只有失敗任務 | 部分任務失敗 |
| Rerun | 所有任務 | 需要全部重跑 |
