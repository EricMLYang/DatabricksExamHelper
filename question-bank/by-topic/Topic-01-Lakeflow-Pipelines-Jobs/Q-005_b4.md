## 題目內容
### 題幹
<!-- ⚠️ 保持英文原文，不要翻譯 -->
A junior data engineer creates a Databricks job with 15 notebook tasks, each performing the same data validation logic on 15 different tables. Each task depends on the completion of the previous one, making the workflow long and difficult to maintain.

What would be a more efficient and scalable solution for this use case?
### 選項
<!-- ⚠️ 保持英文原文，不要翻譯 -->
- **A.** Use a foreach task to run the same validation notebook for each table in parallel, passing the table name as a parameter
- **B.** Schedule 15 separate jobs instead of having multiple tasks in one job
- **C.** Configure the 15 notebook tasks to run in parallel, each with a separate cluster configuration
- **D.** Combine all table validations into one large notebook and loop through all tables sequentially

# 題目解析

---

## 📍 考點識別
**核心技術:** Databricks Workflows - For Each Task
**關鍵概念:** 參數化重用、平行化執行、可維護性
**題目關鍵字：**
- **same validation logic**: 同一個 notebook 重用
- **depends on the completion**: 不必要的序列依賴
- **efficient and scalable**: 需要平行化與參數化

---

## ✅ 正解說明
### 為什麼 A 是正確答案？
For Each Task 可以讓同一個 notebook 以不同參數重複執行，並可設定平行度。對多表同邏輯的驗證而言，**參數化 + 平行化**能大幅縮短流程時間並降低維護成本，因此 A 最符合「效率」與「可擴展」需求。

---

## ❌ 錯誤選項排除
### B. 拆成 15 個 jobs
**為什麼錯誤？**
- 增加管理成本，且無法集中監控與統一參數管理。

### C. 平行 15 個 tasks 且不同 cluster
**為什麼錯誤？**
- 雖可平行，但維護成本更高且不必要；For Each 已能重用同一 task 邏輯。

### D. 單一 notebook 逐一跑
**為什麼錯誤？**
- 仍是序列執行，延長耗時，與「更有效率」相反。
