## 題目內容
### 題幹
<!-- ⚠️ 保持英文原文，不要翻譯 -->
A data engineer uses the following code to process CDC data in Lakeflow Declarative Pipelines:

```sql
CREATE OR REFRESH STREAMING TABLE cdc_target;

CREATE FLOW cdc_flow AS AUTO CDC INTO users_target
FROM stream(users_raw)
KEYS (user_id)
APPLY AS DELETE WHEN operation = "DELETE"
SEQUENCE BY updated_timestamp
COLUMNS *;
```

After running this code, the data engineer noticed that two objects were created the metastore in addition to the users_target table:
- A view named users_target.
- A table named __apply_changes_storage_users_target.

Which of the following correctly explains the purpose of these objects?

### 選項
<!-- ⚠️ 保持英文原文，不要翻譯 -->
- **A.** These objects are used for internal CDC processing leveraging sequence_by along with extra information such as, tombstones and versions required to handle out-of-order data.
- **B.** The view users_target is a materialized snapshot of the raw data, while the table __apply_changes_storage_users_target stores user activity logs for auditing purposes.
- **C.** The users_target view is a virtual index on the target table to speed up queries, and __apply_changes_storage_users_target is a backup of the original users_target index.
- **D.** The view users_target and the table __apply_changes_storage_users_target are temporary objects created for write optimization and are deleted immediately after the pipeline runs.

# 題目解析

---

## 📍 考點識別
**核心技術:** Lakeflow DLP 的 CDC（APPLY CHANGES）內部實作
**關鍵概念:** Tombstones、Versioning、Out-of-order 處理
**題目關鍵字：**
- **AUTO CDC / APPLY CHANGES**: CDC 處理語法
- **__apply_changes_storage_**: 內部儲存表格
- **SEQUENCE BY**: 排序欄位，處理亂序資料

---

## ✅ 正解說明
### 為什麼 A 是正確答案？

**DLP CDC 處理會建立內部物件來管理變更追蹤**：
- **內部表格** (`__apply_changes_storage_*`)：儲存所有 CDC 事件
- **View**：提供乾淨的當前狀態視圖

#### CDC 內部架構
```
CDC 處理架構：
                    users_raw (source)
                          │
                          ▼
               ┌──────────────────────┐
               │   CDC Processing     │
               │ (APPLY CHANGES)      │
               └──────────────────────┘
                          │
           ┌──────────────┼──────────────┐
           ▼                              ▼
┌─────────────────────┐      ┌──────────────────────────────┐
│    users_target     │      │ __apply_changes_storage_     │
│      (VIEW)         │      │    users_target (TABLE)      │
│                     │      │                              │
│ 當前狀態的乾淨視圖  │      │ 儲存：                        │
│ - 只顯示最新版本    │      │ - 所有 CDC 事件              │
│ - 隱藏已刪除記錄    │      │ - Tombstones (刪除標記)      │
└─────────────────────┘      │ - Versions (版本資訊)        │
                             │ - Sequence 資訊              │
                             └──────────────────────────────┘
```

#### 為什麼需要這些物件？

**1. Tombstones（墓碑標記）**
```
處理 DELETE 操作：
├── 不能直接刪除記錄（需要追蹤）
├── 使用 Tombstone 標記已刪除
└── View 過濾掉 Tombstone 記錄
```

**2. Versioning（版本控制）**
```
處理 UPDATE 操作：
├── 同一 Key 可能有多個版本
├── 使用 SEQUENCE BY 決定順序
└── View 只顯示最新版本
```

**3. Out-of-order 處理**
```
亂序資料處理：
├── 晚到的資料可能有較早的 timestamp
├── 內部表格保留所有事件
├── 使用 SEQUENCE BY 重建正確順序
└── View 呈現正確的最終狀態
```

#### 程式碼對應關係
```sql
-- 這段程式碼會建立：
CREATE FLOW cdc_flow AS AUTO CDC INTO users_target
FROM stream(users_raw)
KEYS (user_id)                    -- 用於識別唯一記錄
APPLY AS DELETE WHEN operation = "DELETE"  -- 產生 Tombstones
SEQUENCE BY updated_timestamp     -- 版本排序依據
COLUMNS *;

-- 建立的物件：
-- 1. users_target (VIEW) - 使用者查詢的介面
-- 2. __apply_changes_storage_users_target (TABLE) - 內部儲存
```

## ❌ 錯誤選項排除

### B. view 是 materialized snapshot，table 儲存 audit logs
**為什麼錯誤？**
- **View 不是 Materialized Snapshot**，是動態視圖
- **內部表格不是 Audit Log**，是 CDC 處理的核心儲存
- 用途完全不同

### C. view 是 virtual index，table 是 backup
**為什麼錯誤？**
- **View 不是索引**，是資料的呈現層
- **內部表格不是備份**，是 CDC 處理必需的儲存
- 這些物件是 CDC 運作的核心，不是優化或備份用途

### D. 是臨時物件，執行後刪除
**為什麼錯誤？**
- **這些物件是永久性的**
- 每次 Pipeline 執行都需要這些物件
- 刪除它們會導致 CDC 處理失敗

## 🧠 記憶法
### 口訣
**「內部表存事件，View 呈現當前態」**

### CDC 物件對照表
| 物件 | 類型 | 用途 | 使用者可見 |
|------|------|------|-----------|
| `users_target` | View | 當前狀態視圖 | ✅ 查詢介面 |
| `__apply_changes_storage_*` | Table | CDC 內部儲存 | ❌ 內部使用 |

### CDC 處理流程
```
CDC 資料流：
1. Source 發送事件 (INSERT/UPDATE/DELETE)
2. 事件寫入內部 Storage 表格
3. 標記 Tombstones (刪除)
4. 計算版本順序 (SEQUENCE BY)
5. View 呈現最新狀態
```

### 關鍵概念
```
為什麼不能直接寫入目標表？
├── 需要追蹤歷史變更
├── 需要處理亂序資料
├── 需要標記刪除（而非真刪除）
└── 內部表格解決這些問題
```
