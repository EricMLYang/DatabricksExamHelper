## 題目內容
### 題幹
<!-- ⚠️ 保持英文原文，不要翻譯 -->
A data engineering team manages a multi-task job where each task may be retried multiple times. They noticed that job notifications are not sent when failed tasks are retried.

Which of the following configurations will ensure that a failure notification is received for every failed task?

### 選項
<!-- ⚠️ 保持英文原文，不要翻譯 -->
- **A.** Use task-level notifications in the job definition
- **B.** Implement custom notification logic within each task
- **C.** Create a separate job for each task with job-level retries
- **D.** Disable all task retries to rely on job-level notifications

# 題目解析

---

## 📍 考點識別
**核心技術:** Databricks Jobs 通知機制
**關鍵概念:** Job-level vs Task-level Notifications
**題目關鍵字：**
- **multi-task job**: 多任務 Job
- **notifications not sent**: 通知未發送
- **failed tasks retried**: 失敗任務重試

---

## ✅ 正解說明
### 為什麼 A 是正確答案？

**Task-level Notifications 會在每次任務失敗時觸發**：
- 即使任務之後重試成功，也會發送失敗通知
- Job-level Notifications 只在整體 Job 完成/失敗時觸發
- 要捕捉每次 Task 失敗，必須使用 Task-level 通知

#### Job-level vs Task-level 通知比較
```
Multi-task Job 執行流程：

Task 1: 成功
Task 2: 失敗 → 重試 → 成功
Task 3: 成功
Job: 成功

通知行為：
├── Job-level notification:
│   └── 只在 Job 成功時發送（不知道 Task 2 曾經失敗）
│
└── Task-level notification:
    ├── Task 2 失敗時 → 發送失敗通知 ✅
    └── 每次 Task 狀態變化都會觸發
```

#### 設定 Task-level Notifications
```json
{
  "job_id": 12345,
  "tasks": [
    {
      "task_key": "task_1",
      "notification_settings": {
        "on_failure": ["user@example.com"],
        "on_success": ["user@example.com"],
        "on_start": ["user@example.com"]
      }
    }
  ]
}
```

#### 為什麼這是最佳方案？
```
Task-level Notifications 優勢：
├── 即時通知 → 失敗立即知道
├── 完整追蹤 → 每次失敗都有記錄
├── 內建功能 → 無需自訂程式碼
└── 彈性設定 → 可針對不同 Task 設定
```

---

## ❌ 錯誤選項排除

### B. Implement custom notification logic within each task
**為什麼錯誤？**
- **不必要的複雜度**
- Databricks 已提供內建的 Task-level 通知功能
- 自訂邏輯增加維護成本且容易出錯

```
自訂通知的問題：
├── 需要在每個 Task 中加入程式碼
├── 增加程式碼複雜度
├── 可能因 Task 異常而無法執行
└── 有內建功能為何要自己寫？
```

### C. Create a separate job for each task with job-level retries
**為什麼錯誤？**
- **破壞了多任務 Job 的設計目的**
- 失去任務間的依賴管理
- 過度複雜化架構

```
分離 Job 的問題：
├── 失去依賴關係管理
├── 增加管理複雜度
├── 無法共享 Job 參數
└── 過度工程化
```

### D. Disable all task retries to rely on job-level notifications
**為什麼錯誤？**
- **犧牲了重試機制的價值**
- 暫時性失敗會導致整個 Job 失敗
- 不是解決通知問題的正確方式

```
停用重試的問題：
├── 暫時性錯誤會導致 Job 失敗
├── 降低系統容錯能力
├── 治標不治本
└── 正確做法是用 Task-level 通知
```

## 🧠 記憶法
### 口訣
**「Task 通知即時報，Job 通知等結果」**

### 通知層級比較表
| 特性 | Job-level | Task-level |
|------|-----------|------------|
| 觸發時機 | Job 完成/失敗 | Task 狀態變化 |
| 重試中的失敗 | ❌ 不通知 | ✅ 通知 |
| 設定位置 | Job 設定 | Task 設定 |
| 粒度 | 粗 | 細 |

### 通知設定最佳實踐
```
通知策略設計：
├── 關鍵任務 → 設定 Task-level 通知
├── 監控需求 → 設定 on_failure 通知
├── Job 完成 → 設定 Job-level 通知
└── 除錯需求 → 設定 on_start 和 on_failure
```

### 可用的通知事件
```
Task-level 通知事件：
├── on_start → Task 開始時
├── on_success → Task 成功時
├── on_failure → Task 失敗時
└── on_duration_warning_threshold → Task 超時警告
```
