## 題目內容
### 題幹
<!-- ⚠️ 保持英文原文，不要翻譯 -->
A data engineer has defined the following data quality constraint in a LDP pipeline:

```sql
CONSTRAINT valid_id EXPECT (id IS NOT NULL) _____________
```

Which clause correctly fills in the blank so records violating this constraint will be dropped, and reported in metrics?

### 選項
<!-- ⚠️ 保持英文原文，不要翻譯 -->
- **A.** ON VIOLATION DELETE ROW
- **B.** ON VIOLATION DROP ROW
- **C.** ON VIOLATION FAIL UPDATE
- **D.** ON VIOLATION DISCARD ROW

# 題目解析

---

## 📍 考點識別
**核心技術:** Lakeflow DLP SQL Expectations
**關鍵概念:** ON VIOLATION 子句
**題目關鍵字：**
- **CONSTRAINT ... EXPECT**: SQL 格式的 Expectation
- **dropped**: 丟棄記錄
- **reported in metrics**: 記錄在指標中

---

## ✅ 正解說明
### 為什麼 B 是正確答案？

**`ON VIOLATION DROP ROW` 是正確的 SQL 語法**：
- 違規記錄會被丟棄
- 違規數量會記錄在 Pipeline 指標中
- Pipeline 繼續執行不會失敗

#### 完整語法
```sql
CONSTRAINT valid_id EXPECT (id IS NOT NULL) ON VIOLATION DROP ROW
```

#### SQL Expectation 語法結構
```
CONSTRAINT <name> EXPECT (<condition>) [ON VIOLATION <action>]

Actions：
├── DROP ROW → 丟棄違規記錄，繼續執行
├── FAIL UPDATE → 遇到違規時失敗
└── (不指定) → 保留所有記錄，只記錄指標
```

#### 使用範例
```sql
-- 建立有 Expectation 的表格
CREATE OR REFRESH STREAMING TABLE silver_sales (
    CONSTRAINT valid_id EXPECT (id IS NOT NULL) ON VIOLATION DROP ROW,
    CONSTRAINT valid_price EXPECT (price > 0) ON VIOLATION DROP ROW,
    CONSTRAINT valid_date EXPECT (date IS NOT NULL) ON VIOLATION FAIL UPDATE
)
AS SELECT * FROM STREAM(bronze_sales);
```

#### 指標記錄
```
執行結果會記錄：
├── 處理的總記錄數
├── 通過驗證的記錄數
├── 違規被丟棄的記錄數
└── 每個 Constraint 的違規數
```

---

## ❌ 錯誤選項排除

### A. ON VIOLATION DELETE ROW
**為什麼錯誤？**
- **DELETE 不是正確的關鍵字**
- 正確關鍵字是 DROP
- 這是虛構的語法

```
正確語法：ON VIOLATION DROP ROW
錯誤語法：ON VIOLATION DELETE ROW ❌
```

### C. ON VIOLATION FAIL UPDATE
**為什麼錯誤？**
- **FAIL UPDATE 是讓 Pipeline 失敗，不是丟棄記錄**
- 題目要求「記錄被丟棄」
- FAIL UPDATE 會完全停止 Pipeline

```
行為比較：
├── DROP ROW → 丟棄違規記錄，繼續執行 ✅
└── FAIL UPDATE → 遇到違規就失敗 ✗
```

### D. ON VIOLATION DISCARD ROW
**為什麼錯誤？**
- **DISCARD 不是正確的關鍵字**
- 正確關鍵字是 DROP
- 這是虛構的語法

```
正確語法：ON VIOLATION DROP ROW
錯誤語法：ON VIOLATION DISCARD ROW ❌
```

## 🧠 記憶法
### 口訣
**「丟棄用 DROP，失敗用 FAIL」**

### SQL vs Python Expectation 對照
| SQL 語法 | Python 裝飾器 | 行為 |
|----------|--------------|------|
| 無 ON VIOLATION | `@dlt.expect` | 保留記錄，記錄指標 |
| ON VIOLATION DROP ROW | `@dlt.expect_or_drop` | 丟棄違規記錄 |
| ON VIOLATION FAIL UPDATE | `@dlt.expect_or_fail` | Pipeline 失敗 |

### 完整語法範例
```sql
-- 只記錄，不丟棄
CONSTRAINT c1 EXPECT (col > 0)

-- 丟棄違規記錄
CONSTRAINT c2 EXPECT (col > 0) ON VIOLATION DROP ROW

-- 遇到違規就失敗
CONSTRAINT c3 EXPECT (col > 0) ON VIOLATION FAIL UPDATE
```

### 選擇指南
```
何時使用哪種 ON VIOLATION？

├── 資料品質問題可以容忍
│   └── ON VIOLATION DROP ROW（丟棄壞資料）
│
├── 資料品質必須 100% 正確
│   └── ON VIOLATION FAIL UPDATE（強制修正）
│
└── 只想監控，不想處理
    └── 不加 ON VIOLATION（保留並記錄）
```
