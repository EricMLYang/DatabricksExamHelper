# 題目解析

## 📍 考點識別
**核心技術:** Databricks REST API
**關鍵概念:** Job 與 Run 的識別符
**題目關鍵字：**
- **REST API**: REST API
- **globally unique identifier**: 全域唯一識別符
- **newly triggered run**: 新觸發的執行

---

## ✅ 正解說明
### 為什麼 C 是正確答案？

**`run_id` 是每次執行的全域唯一識別符**：
- 透過 `/api/2.2/jobs/run-now` 觸發 Job 後返回 `run_id`
- 每次 Run 都有獨立的 `run_id`
- 用於追蹤特定執行的狀態和結果

#### API 回應範例
```json
// POST /api/2.2/jobs/run-now
// Request
{
  "job_id": 12345
}

// Response
{
  "run_id": 67890,
  "number_in_job": 5
}
```

#### 識別符關係
```
識別符層級：
├── job_id → 識別 Job 定義（靜態）
├── run_id → 識別特定執行（每次執行不同）
└── task_id → 識別 Job 中的特定 Task
```

---

## ❌ 錯誤選項排除

### A. job_id
**為什麼錯誤？**
- **job_id 識別的是 Job 定義，不是 Run**
- 同一個 Job 可以有多次 Run
- job_id 在多次執行間保持不變

### B. run_key
**為什麼錯誤？**
- **這不是標準的 Databricks API 欄位**
- 不存在於 Jobs API 回應中

### D. task_id
**為什麼錯誤？**
- **task_id 識別的是 Job 中的 Task**
- 不是 Run 層級的識別符
- 一個 Run 可以包含多個 Tasks

---

## 🧠 記憶法
### 口訣
**「Job 定義看 job_id，Run 追蹤看 run_id」**

### 識別符用途對照
| 識別符 | 層級 | 用途 |
|--------|------|------|
| job_id | Job 定義 | 識別 Job 設定 |
| run_id | Job 執行 | 追蹤特定執行 |
| task_id | Task | 識別 Job 中的任務 |
